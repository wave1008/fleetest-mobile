# D-13 レジ: 選択中の住所を「管理」で全削除しても「注文を確定する」が有効のままで、押すと一時障害の文言が出る

| 項目 | 内容 |
|---|---|
| 対象 | ご注文手続き(チェックアウト)/ `CheckoutViewModel` |
| 対応 SC/TC | user-manual §6「両方を選択すると…押せるようになります」/ 観点「住所全削除→確定不可」「選択中の住所削除→整合性」/ test-review-record F1 |
| 重大度 | 高(原因が住所不在なのに「時間をおいて再度」と誤誘導。ユーザーは復旧手順に辿り着けない) |
| 状態 | 起票 |
| 検出 | 手動(探索的テスト)/ iPhone 13・iOS 26.6.1・実機 |
| 起票日 | 2026-08-31 |

**再現手順**
1. ログインし、住所1件以上・支払い方法1件を登録。商品を1点カートに入れ「レジに進む」。
2. お届け先の「管理」→ 住所を全部「削除」→ 戻る。
3. レジ画面が「お届け先が登録されていません」になっているのを確認し、「注文を確定する」を押す。

**期待結果**: 3 の時点でボタンが非活性(住所未選択)。押せたとしても「お届け先を選択してください」。

**実際の挙動**: ボタンは**活性のまま**。押すと **「注文に失敗しました。時間をおいて再度お試しください」**。
サーバは削除済み住所 ID を 400 VALIDATION_ERROR で拒否している。
(カートから入り直すと VM が作り直されて非活性になる = 画面を跨いだ ID の再検証漏れ。)

**証拠**: ft_snapshot `staticText "お届け先が登録されていません"` と `button "注文を確定する" id=btn_place_order`
(disabled 無し)→ tap 後 `staticText "注文に失敗しました。時間をおいて再度お試しください"`。
ソース: `feature/checkout/CheckoutViewModel.kt` `selectedAddressId = state.selectedAddressId ?: …`
(保持 ID を一覧と照合しない)/ `server/.../OrderStore.kt` `place` の 400。

**仕様裁定(要判断があれば)**: 一覧更新のたびに `selectedAddressId`/`selectedPaymentId` が一覧に存在するか
検証して無ければ null に戻す。400 の理由(住所/支払い不正)は文言を分ける。
