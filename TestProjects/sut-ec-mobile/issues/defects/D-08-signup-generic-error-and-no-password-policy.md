# D-08 サインアップ: 失敗理由が「登録に失敗しました」に丸まる / パスワード1文字・メール「@」だけで登録できる

| 項目 | 内容 |
|---|---|
| 対象 | 登録(サインアップ)画面 / サーバ `POST /auth/signup` の検証 |
| 対応 SC/TC | 観点「異常系 › 入力バリデーション」/ user-manual §9 |
| 重大度 | 中(理由が伝わらない・実質無検証のパスワード) |
| 状態 | 起票 |
| 検出 | 手動(探索的テスト)+ API 直叩き / iPhone 13・iOS 26.6.1・実機 |
| 起票日 | 2026-08-31 |

**再現手順**
1. アカウント → ログイン / 登録 → アカウントを作成。
2. お名前 `テスト`、メール `abc`、パスワード `1` で「登録」。
3. (API)メール `x@example.com` / パスワード `1` で登録。メール `@` / パスワード `1` で登録。

**期待結果**: 2 は「メールアドレスの形式が不正」など理由が示される。3 はパスワード方針
(最低長など)とメール形式で弾かれる。

**実際の挙動**: 2 はサーバが `400 {"code":"VALIDATION_ERROR","message":"email is invalid"}` を返して
いるのに、画面は **「登録に失敗しました」** のみ(重複メールの 409 と区別できない)。
3 は **パスワード `1` で 201 登録成功**、**メール `@` でも 201 登録成功**(検証は `contains("@")` だけ)。

**証拠**: ft_snapshot `staticText "登録に失敗しました"`(メール `abc`)。
`curl -X POST /api/v1/auth/signup -d '{"name":"x","email":"@","password":"1"}'` → HTTP 201。
ソース: `server/.../plugins/Validation.kt`(`!r.email.contains("@")` のみ・password の長さ規則なし)/
`feature/auth/SignupViewModel.kt`(error を真偽値に畳む)。

**仕様裁定(要判断があれば)**: パスワードの最低長・メール形式をサーバで定め、
サーバの `message` をそのまま(または対応する訳文で)画面へ出す。
