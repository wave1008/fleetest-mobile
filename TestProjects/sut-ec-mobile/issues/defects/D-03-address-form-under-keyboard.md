# D-03 住所フォーム: キーボードが立つと下部の入力欄に触れなくなる(4.7インチ実機)

| 項目 | 内容 |
|---|---|
| 対象 | 住所を追加 / フォーム全体のキーボードインセット |
| 対応 SC/TC | なし(レイアウト不具合。TC 由来ではない) |
| 重大度 | 高(**その欄に入力できない** = 住所登録が完了できない) |
| 状態 | 起票 |
| 検出 | 自動シナリオ `注文履歴に確定した注文が並ぶこと.S0010` / **iPhone SE(第3世代)・iOS 26.5.2・375x667** |
| 起票日 | 2026-08-27 |

**再現手順**
1. iPhone SE(第3世代)など **667pt 高**の端末で「アカウント → お届け先 → 住所を追加」を開く。
2. 上から順に入力していく(氏名 → 郵便番号 → 都道府県 → 市区町村 → 番地)。
3. 「電話番号」欄に触れようとする。

**期待結果**: 電話番号欄に焦点が移り、入力できる。

**実際の挙動**: キーボードが画面下半分を占め、電話番号欄は**その下に隠れている**。
フォームはキーボードぶんのインセットを持たず、**内容が容器に収まっているためスクロールもできない**
ので、指でもツールでも触れられない。触ろうとしたタップはキーボードに当たり、**焦点は直前の欄に
残ったまま**なので、打鍵がその欄へ流れ込む(下の証拠を参照)。

**証拠**(実機 run `scenario-20260827-053313-887`):

```
容器(scrollView) = (0,0 375x667)      ← 画面いっぱい。内容は保存ボタンまで約 570pt で収まる
キーボード(inputView) = (0,407 375x260)
電話番号 = (16,441 343x65)             ← 中心 473 がキーボードの内側
番地・建物名 value="千代田1-1t09012345678090123456780…"  ← 電話番号の打鍵が流れ込んだ
```

ツールは「覆われている欄は送って外してから打つ」動作を持つ(docs/commands.md §縁の帯に潜った対象)。
**番地の欄はこれで解決した**が、電話番号の欄は**送る余地が無い**ため外せない。
ツールは動かなくなった時点で諦め、読み返しで 422 として止める(誤った緑にはしない)。

**影響範囲**: 背の高い端末(iPhone 15 Pro・シミュレータの iPhone 17 Pro)では余白に収まるため
露見しない。フォーム全般(支払い方法の追加など)に同じ形がある可能性がある。

**仕様裁定(要判断)**: 実装側でキーボードのインセット(`imePadding` 相当)を入れ、キーボードが
立っている間はフォームを送れるようにする。テスト側の回避(キーボードを閉じてから打つ)は
**利用者の実害を隠す**ため本不具合の対処にはしない。

**追記(2026-08-31・iPhone 13 / iOS 26.6.1 / 390x844pt でも再現)**: 電話番号欄は
y=590〜655 でキーボード(y≥509)の下。タップはキーボードに当たり、焦点が「番地・建物名」に
残ったまま打鍵が流れ込み **`1-1gabcabcabcabc`** になった(`g` はキー誤打・`abc`×4 は
ツールの再送)。フォームは 57pt しかスクロールできず(y=533 で依然キーボード下)、
キーボードを Return で閉じてからしか触れない。**844pt でも起きる**。同根: D-18(保存ボタン)。
