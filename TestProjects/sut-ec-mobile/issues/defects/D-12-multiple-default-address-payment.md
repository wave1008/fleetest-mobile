# D-12 住所・支払い方法: フォームの「既定に設定」スイッチで既定が2件同時に立つ

| 項目 | 内容 |
|---|---|
| 対象 | 住所を追加/編集・お支払い方法を追加/編集 / サーバ `upsertAddress` / `upsertPayment` |
| 対応 SC/TC | user-manual §10「「デフォルト(既定)」の住所には印が付きます」(単数) |
| 重大度 | 中(レジで自動選択される住所が不定になる) |
| 状態 | 起票 |
| 検出 | 手動(探索的テスト)/ iPhone 13・iOS 26.6.1・実機 |
| 起票日 | 2026-08-31 |

**再現手順**
1. ログイン → お届け先住所 → 追加 → 必須欄を埋め「既定の住所に設定」ON で保存(1件目)。
2. 別の住所を「編集」で開き、「既定の住所に設定」ON で保存。

**期待結果**: 既定は常に1件。後から ON にした方だけに「既定」が付き、他方は外れる。

**実際の挙動**: **両方の住所に「既定」バッジ**が付く。一覧の「既定に設定」ボタン経由
(`setDefaultAddress`)だけが他を外す。レジ画面はどちらか一方(先頭)を勝手に選ぶ。

**証拠**: ft_snapshot(お届け先住所)`staticText "既定"` ×2([1984] / [1993])、
どちらの行にも「既定に設定」ボタンが無い。
ソース: `server/.../repository/AccountStore.kt` `upsertAddress`/`upsertPayment` が
`it[isDefault] = a.isDefault` を書くだけで他行を落とさない。

**仕様裁定(要判断があれば)**: upsert で `isDefault=true` のときは同一ユーザーの他行を false にする
(`setDefault*` と同じトランザクション)。支払い方法も同型。
