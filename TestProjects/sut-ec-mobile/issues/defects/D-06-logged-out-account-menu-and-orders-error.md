# D-06 アカウント: 未ログインでもメニューが並び、「注文履歴」を開くと通信エラーの文言が出る

| 項目 | 内容 |
|---|---|
| 対象 | アカウント / 注文履歴(未ログイン時) |
| 対応 SC/TC | user-manual §9「ログインしていないとき」(「ログイン / 登録」ボタンのみ) |
| 重大度 | 中(未ログインが原因なのに「接続を確認して」と誤誘導。再試行しても永久に失敗) |
| 状態 | 起票 |
| 検出 | 手動(探索的テスト)/ iPhone 13・iOS 26.6.1・実機 |
| 起票日 | 2026-08-31 |

**再現手順**
1. ログアウト状態でアカウントタブを開く。
2. 「注文履歴」をタップする。

**期待結果**: 未ログイン時はメニューを出さない(または「ログインが必要です」と案内する)。

**実際の挙動**: 「ログイン / 登録」の下に「注文履歴 / お気に入り / お届け先住所 / お支払い方法 /
UIベンチマーク」が並ぶ。「注文履歴」を開くと **「読み込みに失敗しました / 接続を確認して、もう一度
お試しください」+「再試行」** が出る(サーバは 401 を返している)。「お届け先住所」は
「登録済みの住所がありません」と空扱いになり、追加して保存した時点で初めて
「ログインが必要です」と言われる(フォーム入力は失われる)。

**証拠**: ft_snapshot(未ログイン → `#btn_orders`)
`staticText "読み込みに失敗しました"` / `staticText "接続を確認して、もう一度お試しください"` /
`button "再試行" id=btn_retry`。
ソース: `feature/profile/AccountScreen.kt`(MenuRow が無条件)/
`data/repository/impl/RemoteOrderRepository.kt`(`get("orders")` に認証ガード無し → 401 で `body<List<Order>>()` が例外)。

**仕様裁定(要判断があれば)**: マニュアル §9 どおり未ログイン時はメニューを隠す。残すなら 401 を
「ログインが必要です」として区別する。
