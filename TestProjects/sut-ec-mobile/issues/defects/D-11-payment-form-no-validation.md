# D-11 支払い方法: ブランド空・カード番号1桁・月13・過去の年がそのまま保存され「 •••• 1」「13/2000」と表示される

| 項目 | 内容 |
|---|---|
| 対象 | お支払い方法を追加/編集 / サーバ `POST /payment-methods` |
| 対応 SC/TC | 観点「異常系 › 非数字(カード)・過去日付の有効期限」/ user-manual §11 |
| 重大度 | 中(決済情報として成立しない値が保存され、レジの選択肢にも出る) |
| 状態 | 起票 |
| 検出 | 手動(探索的テスト)/ iPhone 13・iOS 26.6.1・実機 |
| 起票日 | 2026-08-31 |

**再現手順**
1. ログイン → アカウント → お支払い方法 → 追加(カード)。
2. ブランド 空、カード番号 `1`、名義人 `T`、有効期限 月 `13` 年 `2000` で保存する。

**期待結果**: 番号桁数・月(1〜12)・有効期限(未来)・ブランドの検証で弾かれる。

**実際の挙動**: 保存される。一覧は **「 •••• 1」**(先頭に空白 = ブランド空)と **「T  13/2000」**。
レジ画面の支払い選択肢にも「 •••• 1」として並び、注文詳細のお支払いにも写る。

**証拠**: ft_snapshot(お支払い方法)`staticText " •••• 1"` / `staticText "T  13/2000"`。
ソース: `feature/address/PaymentEditViewModel.kt`(`expMonth = state.expMonth.toIntOrNull() ?: 0`・
`last4 = cardNumber.takeLast(4)`・brand 未検証)/ `PaymentMethodsScreen.kt` の表示式。

**仕様裁定(要判断があれば)**: 番号は数字 14〜16 桁、月 1〜12、年月が当月以降、ブランド必須を
クライアント・サーバ双方で検証する。
