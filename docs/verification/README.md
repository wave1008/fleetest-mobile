### [constraints.md](constraints.md) — 検証: 制約と回避

- iOS(XCUITest・Simulator・in-app)
  - 再起動直後の最初の xcuitest 供給は冷えたブートがランナーの予算に混ざる(2026-09-14)
  - Mac の再起動の後、シミュレータのソフトキーボードが出なくなる(2026-09-19)
  - 長く生きた XCUITest ランナーは AX 照会のたびに数秒待つ状態に落ちることがある(2026-09-14)
  - 高負荷では XCUITest の `typeText` が打鍵を取りこぼす(2026-07-31)
  - 同時刻クラスタは環境要因(kAXErrorAPIDisabled・2026-08-04)
  - WebView の入力が黙って落ちる(domInterop・2026-08-04)
  - iOS シミュレータも「画面だけ死ぬ」——a11y は健全・タップだけ届かない(2026-08-05 実測)
  - スクロール探索の「飛び越し」を決定的に再現する(2026-08-06)
  - 端に着いたら探索を打ち切り、逆向きに拾い直す(2026-08-06)
  - ghost へのタップ防御は「そのステップが探索したか」を条件にしてはいけない(2026-08-06)
  - 画面外要素の frame は信用できない —— XCUITest は容器の原点へクランプする(2026-08-05 実測)
  - SpringBoard の確認アラートはアプリスコープのスナップショットに出ない(2026-08-09)
  - 常駐ブリッジのセッション(iOS xcuitest を CLI で直接叩くとき)
  - 未インストールのアプリを launch するとランナーが死ぬ(2026-08-06)
- Android
  - ポーリングはキャッシュを突破しない —— 「撮り直せば新しくなる」は Android では偽(2026-08-14)
  - Android ブリッジの版を上げた直後の1回目は落ちることがある(2026-08-01)
  - Android の実行時間はセッション内で劣化する(前後比較は必ず同セッションで取り直す)
  - Android 凍結まわりの検証の罠
- FM(Foundation Models)
  - FM が死んでいる run は「守りが効いていない run」(2026-08-20 に可視化)
  - FM 呼び出しの許可枠(FMCallSlots)
  - サーキットブレーカ(FMBreaker)

### [triage.md](triage.md) — 検証: 切り分け(全滅・誤った赤・画面が変わらない)

- 既知の間欠失敗(2026-08-13 時点)
- ブリッジの「誤った赤」を疑う手順(成功しているのに失敗と報告される)
- 操作は ✅ なのに画面が変わらないとき
- FM(Foundation Models)が全滅したら
- デバイス供給の競合(モニターと run が同じデバイスを取り合う)
- iOS が `never joined the run` / 「the in-app bridge did not respond in time」で供給に失敗したら
- macOS / Xcode ベータの整合
- テストが接続拒否(「ドライバへの接続が拒否されました」)で全滅したら
- ワーカーが「ブリッジ接続不能のため離脱しました」で落ちたら
- iOS の Compose・Flutter が「文字が描かれていない」「screen rendering check」で全滅したら
- テストが「Application is not running」で全滅したら

### [judgment.md](judgment.md) — 検証: 判定の規律(flake・性能・A/B)

- flake・性能の判定規律(1回の結果で断じない)
- 検証は重ねない —— デバイス実行中に本線をビルドしない
- in-app ブリッジの A/B は「dylib が本当に入れ替わったか」を先に確かめる
- 旧版のブリッジとの A/B は「旧ソースを現行の版番号で」ビルドする
- in-app の整定が cap に張り付いているかを見る
- 効果は「率」だけでなく「失敗の質」で見る
- 過去の実行データは「再現しなくても機構を確定できる」検体庫
- フレークの集計は「調査由来の失敗」を除いてから読む
- デバイス基盤の一過性エラーは「テストの失敗」と数えない
- 低頻度すぎて追えない失敗は、母数を書いて止める

### [testing.md](testing.md) — 検証: 検知・テスト・調べ方の規律

- 「待ってから取り直す」を模すフェイクは**動く木**にする
- 私有 API の意味論は推測せず実採取する
- アプリの描画の時刻は SUT の描画プローブで採る
- 「動き続ける画面」の対照はアニメーションで作らない —— E2E はアプリのアニメーションを止めて回す
- ブリッジが「何を見ているか」は使い捨てのプローブ版で採る
- 「回復したら公表を消す」は分岐ごとに書くと必ず片方を落とす
- 「画面が一様」は凍結の代理指標として弱い —— 初回描画待ちを凍結と誤認していた
- 検知の「誤検知0」は、常に false を返す検出器と区別できない
- めったに撃たない経路は、緑を重ねても検証されない
- 同じ機構を通る2経路で片方だけ失敗したら、機構でなく前提条件を疑う
- 切り分けは「実験系が効いているか」を先に確かめる
- 純粋関数が全部正しく緑でも、その入口に一度も入らなければ何も直っていない
- 陽性対照は「実装の誤り」だけでなく「設計と文言の嘘」も暴く
- 失敗の帰属は「HEAD での対照」で決める
- 単体テストが緑でも「実データで1回動かす」まで信用しない
- 自前 SUT に witness が無い形は、受け手の環境で取れたら台帳に書く
- 新しい検知・警告は「既存資産の全数に当てて誤検知0」まで確認する
- 注記は「読んだ印象」でなく「まっさらなエージェントの手数」で足し引きする
- 注記の発火と出力コストはコーパス全数で台帳にする
- テストは「通ること」でなく「破ったら落ちること」を確認する
- 拡張 webview のテストは jsdom にレイアウトが無い
- 排他は TSan で見る
- 調査用の計装は「恒久的な診断」として残る形で入れる
- 撃つ前に何を見たかは FT_BRIDGE_TRACE で採る
- 既存テストは無料の「全数当て」
- 「届いていない」を推論で説明しない —— 生イベントを SUT 側で測る
- 決定は「根拠が消えたか」で見直す
- 検証に使う口と本番の口はモードまで揃える
- プロトコルの既定実装は「実装漏れ」を黙って隠す
- 「このフレームワークでは無理」は経路ごとに測り直す
- デバイス上で説明がつかないときは、修正案より先に画面を撮る

### [operations.md](operations.md) — 検証: E2E の運用

- macOS・Xcode を上げたら `--retrain-classifiers` を1回付けて回す(2026-10-07)
- 1回の実行が見るのは iOS の2モードのうち片方だけ
- 入力・キー系は Compose だけで検証しない(フレームワークで経路が割れる)
- モニターと E2E(**止めるのは性能を測るときだけ**。2026-08-21 に運用変更)
- 実機の E2E は `Scripts/e2e-devices.sh`(2026-10-13)
- クラッシュダイアログは回帰スクリプトが止めて戻す(2026-10-03)
- 覆い(別ウィンドウのモーダル)の witness は E2EAppIOS にある(2026-08-20)
- 検証スクリプトそのものの罠
- `Scripts/e2e.sh`(fleetest 自身の E2E)
- SUT の Info.plist はコミットするソース —— URL スキーム等は直接編集する
- E2E を同時に2つ走らせない(2026-08-09)
- 受け手フロー(preflight / install.sh)の検証
- 常駐プロセスの掃除
- 実機(kind: physical)の検証
- 録画(record:true)の検証
- ブリッジ版数の上げ忘れ検出(2026-07-30)
