# 仕様上の欠陥の監査(2026-10-19〜20)の記録

2026-10-19〜20 の仕様監査(文書と実装の食い違い・未定義・沈黙する縮退)で見つけた項目は、すべて片付けた。
推測のまま残った2件は docs/open-issues.md の「再現の材料が要るもの」へ移した。
ここに残すのは、**欠陥に見えて欠陥ではなかったもの**(再調査を省くため)と、片付けたときの決定の記録だけ。
番号は監査時の通し番号(本文はコミット履歴の docs/spec-defects.md にある)。

## 欠陥ではなかったもの(再調査を省く)

- **可視性検証の親スイッチが幾何の段まで切る**(旧 3 番): 意図した契約だった。`fmTextVisibilityCheck` と
  `ocrTextVisibilityCheck` を両方 false にすると、画面外の要素も `exist` が素通りする。docs/commands.md の `requireVisible` は
  「確認が実際に走るのは…が有効な run」と書き、`StepExecutorTests.testOffscreenMatchPassesWhenTheVisibilityGuardIsOff` が
  この形を固定している。幾何の段だけを常に効かせるなら、この契約を変える決定が要る(既定はどちらも true なので、効かないのは両方を切った run だけ)
- **`fold` / `unfold` / `hinge` の非対応の実機の扱いが OS で割れる**(旧 27 番): 意図した設計。iOS 実機は折りたためるかを観測できないので、分からないものを黙って対象外(skipped)にせず失敗にする。docs/commands.md の `fold` に「物理端末は非対応で失敗」と明記がある。Android 実機は `device_state` で折りたためるかを読めるので、折りたためない機は skipped になる
- **`type("…")` の1引数形がセレクタらしい文字列を断る**(旧 33 番): 利用者向けの type のページ(ja/en)に、断る理由と2引数形の逃げ道が既に書いてある
- **iOS の `back()` が結果を確かめない**(旧 23 番): DSL の `back()` は前後の木を読み比べ、変わらなければ注記 `backIneffective` を残す(`FTCore.BackEffect` を MCP の `ft_navigate` と共有)。監査ではドライバの `back()` だけを読んでいた
- **Android 実機だけの run でも公開ポートを LAN に開く**(旧 41 番): 意図した設計。Android 実機のアプリが LAN のアドレスを焼き込んでビルドされていれば `adb reverse` では届かないので、LAN 公開と reverse の両方を用意する。docs の「実機のレーンを含む run では必須」と一致

## 片付けたときの決定

高 × 小は 2026-10-20 に片付けた(1・2 は修正、3 は設計どおりと確認、7 は docs への明記)。高 × 中も同日に片付けた(5 は修正、6 は治した回の印まで)。コスト小も同日に片付けた(17 は直し方を詰めるとブリッジの版上げが要るので中へ、27・33 は欠陥ではなかった、45 は実測して docs へ明記)。コスト中も同日に片付けた(17・18・19・20・25・45 は修正 = 20 は別アプリの launch を断る形、21 は `screenshot()` だけ、23・41 は欠陥ではなかった)。6(自己修復)は決定済みで片付けた: 既定 ON のまま、直したセレクタは実行の終わりにシナリオのソースへ自動で書き戻す(git 前提。利用者が差分を見てコミットする)。VSCode の確認パネルと `fleetest api apply-heal` は撤去し、通知に置き換えた(`HealSourceWriteBack`。機械ごとに分かれる run は親が全部の子のあとで1回だけ書く)。要決定だった 4 件も片付けた: 7 は止める口を置かない(シナリオは最初から再実行されても壊れないように書く、と docs に明記)、22 は `beforeAll()` を足し、メモを run 共有にした(書き込みのロックは持たない = 制約として docs に明記)、24 は `screenLooksLike` をアサーションに数えない、34 は `@TestClass(app:)` を廃止し、アプリは実行プロファイルが決める(プロファイル無しは `--app-id`)。4 は修正した(Wi-Fi の iOS 実機のブリッジは `127.0.0.1` の中継を通し、サンドボックスは外のホストを開けない)。26 は `--profile` 付きの dry-run の警告にした(索引の `unsupportedOn` = `DSLCommandIndex.unsupportedTargets` をプロファイルのデバイスのモード・種別と照合。名前だけで決まるコマンドに限り、引数・UI フレームワークで決まるものと MCP の `ft_dry_run` は対象外)。21 は、画像判定の絵を覆いがあると分かっているときだけ XCUITest で撮るようにした(ユーザー決定。inapp モードでキーボードを木が申告しているとき・CAE フェーズごとに1回の照会でシステムアラートが前面にあったとき。screenLooksLike / screenIs は常に画面全体。通知バナー等とフェーズ途中のアラート・XCUITest ブリッジが無いときは見逃す = 利用者向け docs の制限)。
