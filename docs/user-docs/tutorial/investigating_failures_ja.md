# 結果を読み、失敗を調べる

テストを実行するたびに、成否を問わず結果が残ります。読むのも AIアシスタントに任せられます。

## 結果を要約してもらう

### AIへの指示文

```text
fleetest の直近の実行結果を要約し、失敗があれば、失敗したシナリオと落ちた手順を一覧にして。
```

<details>
<summary><b>手動で実行(クリックで詳細表示)</b></summary>

- `TestProjects/<プロジェクト>/reports/` にシナリオごとの Markdown レポートがあります。
- VSCode では Test Explorer が成否を直接表示し、そこからレポートを開けます。
  コマンド「fleetest: 結果ダッシュボードを開く」で、実行の履歴と成功率も見られます。

</details>

## 失敗の原因を調べてもらう

レポートには、失敗した手順・失敗メッセージ・**失敗した瞬間の画面の要素一覧とスクリーンショット**が
載っています。AIアシスタントはそれを読んで、何が起きたかを説明できます。

下は実際のレポートの抜粋です(サンプルアプリで、カートに追加したときの一瞬だけ出る表示を待って落ちた例)。

<img src="../images/tutorial/ja/report_failure.png" width="600" alt="失敗したレポートの抜粋。落ちた手順と失敗メッセージ、失敗した瞬間の要素一覧(折りたたみ)とスクリーンショットが載っている">

### AIへの指示文

```text
fleetest の直近の実行で落ちたシナリオについて、レポートから原因を調べて。
アプリの不具合らしいのか、テストの書き方の問題らしいのかも分けて報告して。シナリオはまだ直さないで。
```

**「直さないで」を添えるのが大事です**。AIアシスタントに調査と修正を同時に頼むと、
アプリの不具合で落ちたテストを「期待値をアプリに合わせる」形で通してしまうことがあります。
それはテストが不具合を見逃すようになることを意味します。報告を読んでから、直すかどうかをあなたが決めてください。

### 原因の見当がついたら

| 見当 | 次の頼み方 |
|---|---|
| アプリの不具合 | テストはそのまま。アプリを直したら「前回落ちたシナリオだけを実行し直して」 |
| 画面が変わってテストが古くなった | 「〜の画面が変わったので、このシナリオを今の画面に合わせて直して」([追従させる](keeping_up_with_app_changes_ja.md)) |
| 出たり出なかったりするダイアログが割り込んだ | 「起動直後に〜のダイアログが出ることがある。出たら閉じてから進むように直して」 |
| よく分からない | 「このシナリオを5回実行して、落ちる回と通る回で何が違うかを調べて」 |

## fleetest は原因を決めつけない

fleetest の記録に残るのは、**どの段階で・どの操作が・どう失敗したか**という事実だけです。
「アプリが重かった」「Mac が混んでいた」のような原因の推測は記録しません —— ツールにはそれを
区別する手段が無く、推測で書くと誤った判断を生むからです。AIアシスタントの説明も、レポートに
書かれた事実を根拠にしているかを確かめながら読んでください。

## 不安定なテストを見つける

何度も回していると、通ったり落ちたりするテストが見えてきます。

### AIへの指示文

```text
fleetest の過去の実行結果から、通ったり落ちたりする不安定なシナリオと、遅くなってきたシナリオを洗い出して。
```

<details>
<summary><b>手動で実行(クリックで詳細表示)</b></summary>

```bash
../foundation-tester/.build/debug/fleetest results flaky      # 成功も失敗もするシナリオ
../foundation-tester/.build/debug/fleetest results insights   # 退行・連続失敗・遅くなったシナリオ・特定デバイスへの偏り など
../foundation-tester/.build/debug/fleetest results slow       # 平均所要時間が長い順
```

</details>

## 実行の様子を見返す

- 録画は既定で有効で、シナリオごとの動画が残ります(容量を抑えたいときは「失敗したシナリオの録画だけ残して」と
  頼めます)。録画は VSCode 拡張の「テストセッション」タブで見られます([VSCode で見る](watching_in_vscode_ja.md))。
- シナリオごとの実行ログ(各手順の成否と、実行中に出た出力)も残っています。
  「直近の実行のログインのテストの実行ログを見せて」と頼めば読めます。

## fleetest 自体の不具合かもしれないとき

AIアシスタントに調べてもらっても原因がツールの側にありそうなら、保守者へ報告してください。
報告に添える診断情報のまとめ方は[トラブルシューティング](../in_action/troubleshooting_ja.md)にあります。
