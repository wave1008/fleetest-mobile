# アプリの変更にテストを追従させる

[in English](keeping_up_with_app_changes.md)

アプリは変わり続けます。そのたびにテストを直す作業も、AIアシスタントに任せられます。

## 小さな変化は自己修復が吸収する

ボタンの ID だけが変わって、文言(ラベル)が同じ、という変化は fleetest の自己修復がその場で吸収し、テストを続けます。
通った手順のセレクタは実行の終わりにシナリオのソースへ自動で書き戻されるので(git 管理が前提)、差分を確認してコミットします。

### AIへの指示文

```text
fleetest のテストプロジェクト myshop で、自己修復がシナリオに書き戻したセレクタを git の差分で確認して。
妥当なものは残し、そのシナリオを実行して通ることを確かめて。
```

<details>
<summary><b>手動で実行する場合(クリックで詳細表示)</b></summary>

VSCode の Test Explorer から実行した場合は通知が出るので、「変更を表示」でソース管理ビューを開き、git の差分を確認してコミットします。
書き戻したくないときは、実行プロファイルの `heal` を `false` にして自己修復を切ります。

</details>

## 画面が変わったとき

画面のレイアウトや手順そのものが変わったときは、自己修復では追いつきません。何が意図した変更かを添えて指示します。

### AIへの指示文

```text
My Shop のログイン画面が新しいデザインに変わった(メールアドレスとパスワードが別の画面に分かれた)。
fleetest のテストプロジェクト myshop のログインに関係するシナリオを今の画面に合わせて直し、実行して確かめて。
アプリの不具合で落ちているテストまで、通るように書き換えないで。
```

## 新しい割り込みが増えたとき

お知らせダイアログ・アンケート・OS の許可ダイアログが増えて、多くのテストが一斉に落ちたときは、まとめて扱うよう指示します。

### AIへの指示文

```text
My Shop の起動直後に、ときどき「新機能のお知らせ」ダイアログが出るようになった。
fleetest のテストプロジェクト myshop のどのテストでも、このダイアログが出たら「閉じる」を押して先へ進むようにして。
```

## テストを壊れにくくする

### AIへの指示文

```text
fleetest のテストプロジェクト myshop のシナリオを見直して、アプリの文言変更や画面サイズの違いで壊れやすい書き方があれば一覧にして。
直すのは、私が一覧を確認してからにして。
```

観点は[壊れにくいシナリオの書き方](../reference/writing/writing_robust_scenarios_ja.md)にあります。

## 使わなくなったテスト

画面ごと無くなった機能のテストは、削除せずに「廃止」の印を付けて残せます(印の付いたテストは、名指ししたときだけ実行されます)。

### AIへの指示文

```text
My Shop のクーポン画面は廃止された。fleetest のテストプロジェクト myshop のクーポンに関係するシナリオに廃止の印を付けて。
```
