# リモート実行

`fleetest run --runner <マシン名>` を使うと、テストを別の Mac(ランナー機)で実行できます。
手元の Mac から SSH で run を送り、ランナー機でふつうに実行して、出力と成果物を手元へ持ち帰ります。

このページでは、できることと仕組みをまとめます。セットアップの手順は
[リモートランナーのセットアップ](remote_runner_setup_ja.md)にあります。

## できること

| できること | 対応 |
|---|---|
| 別の Mac へ run を送って実行する(CLI・VSCode 拡張のどちらからでも) | ✅ |
| 実行中の進み具合の表示・キャンセル・タイムアウト | ✅ |
| レポート・JUnit・録画・run ログを手元へ回収する | ✅ |
| ランナー機の導入を手元から1コマンドで行う(`remote setup`)。撤去も1コマンド(`remote teardown`) | ✅ |
| 複数のランナー機をまとめて診断・掃除する(`remote status` / `remote clean`) | ✅ |
| ランナー機で `fleetest` のコマンドを1つだけ実行する(`remote exec`) | ✅ |
| 複数のランナー機で同時に実行する(フリート。`run --fleet`) | ✅ |
| 1組のシナリオを複数のランナー機に振り分ける(`run --fleet <名前> --split`) | ✅ |
| リモートで実行した結果も `fleetest results` の集計(flaky 検出など)に含める | ✅(既定で回収) |
| モニターの「テスト実行」タブで、リモートのデバイスの状態と映像を見る | ✅ |

シナリオとプロファイルは、実行のたびに手元からランナー機へ自動で送られます。
編集は手元だけで行い、ランナー機のファイルを直接編集することはありません。

## 全体像

```
発行側の Mac(手元)                     ランナー機
fleetest run --runner mac2 …             ~/fleetest-runner/               ← 専用ベースディレクトリ
  ├ 適合チェック(rev・Xcode)   ssh     ├── foundation-tester/          ← ツール本体のクローン(名前固定・共有)
  ├ 転送(rsync: シナリオ・設定) ────>  └── users/<issuerId>/work/      ← あなたの作業場所(発行者ごと)
  ├ 出力を受け取って表示                     ├── TestProjects/<プロジェクト>/
  └ 成果物を回収 <───────────────────      └── .build/
```

リモート実行で使うのは、ランナー機の `~/fleetest-runner/` の中だけです。
ランナー機に foundation-tester が別に入っていても、それには一切触りません。

## セットアップ

ランナー機のセットアップ手順は、CLI と VSCode 拡張の両方について
[リモートランナーのセットアップ](remote_runner_setup_ja.md)にまとめてあります。流れは次のとおりです。

1. ランナー機を準備する(ランナー機で・手作業)
2. SSH の鍵でログインできるようにする
3. マシンを登録する
4. ランナー機に fleetest を入れる(`fleetest remote setup`)
5. ランナー機のデバイスをプロファイルに入れる
6. つながるか確認し、最初のテストを実行する

Claude Code では、`/fleetest:fleetest-remote-setup` スキルでもセットアップできます。
スキルは必要なことを質問し、機械的な作業は `fleetest remote setup` に任せ、人の手が要る作業は
あなたに渡して、最後に結果を報告します。ランナー機の準備のように sudo や画面操作が要る作業は、
スキルは代わりに行いません。

## マシン名

ランナー機を指すときは、ホスト名や IP アドレスではなく、手元で付けた名前を使います。
この名前を**マシン名**と呼びます。

- **ホスト(host)**: ネットワーク上の実際の宛先です。例: `<user@192.168.xxx.xxx>`
- **マシン(machine)**: そのホストに付ける、この Mac の中だけで通じる名前です。例: `M1Max`。
  プロファイルに書くのはこちらです。

マシン名は `fleetest remote machines add` か、デバイスモニターの「設定」タブで登録します
(手順は[リモートランナーのセットアップ](remote_runner_setup_ja.md)のステップ2)。

マシン名はあとから変えても困りません。結果 JSON などの記録にはホスト名が残り、
ランナー機へ送るファイルや引数にもマシン名は出てこないためです。

## どのマシンで実行するかはマシンプロファイルで決まる

マシンプロファイルでは、デバイスごとに `machine` にマシン名を書きます。

```jsonc
// profiles/machines/M1Max.json
{ "machine": "M1Max",
  "ios": { "devices": [ { "machine": "M1Max", "name": "simulator1", "simulator": "iPhone 17 Pro" } ] } }
```

実行プロファイルは、使うマシンプロファイルを名前で指定します。そのため、
**実行プロファイルを選べば、どのマシンで実行するかも決まります**。ふだんは `--runner` を
付ける必要はありません。

- 手元の Mac のデバイスには `"machine": "local"` と書きます。省略すると、ファイル直下の
  `machine` の値を引き継ぎます。手元とリモートのデバイスを1つのファイルに混ぜると違いが
  出るので、省略しないでください。
- コマンドラインで `--runner <名前>` を付けると、プロファイルの指定より優先されます。
  `--runner` にはマシン名のほか、ホスト名や IP アドレスを直接書くこともできます。
- 古いキー名 `"host"` で書いたプロファイルも、そのまま読めます(2026-08-26 に `machine` へ改名)。

## `run --runner` と `--fleet`

```bash
fleetest run --runner <名前> --profile <実行プロファイル>        # この回だけ特定のマシンへ送る
fleetest run --project <プロジェクト> --fleet <名前>             # フリートの全マシンで同じシナリオを実行する
fleetest run --project <プロジェクト> --fleet <名前> --split      # シナリオを全マシンに振り分けて実行する
```

フリートは、マシンと実行プロファイルの組を並べたものです。
`TestProjects/<プロジェクト>/profiles/fleets/<名前>.json` に、`host`(マシン名)と
`profile`(実行プロファイル名)の組を並べて定義します。手元の Mac は `"local"` と書きます。

- `--split` を付けると、同じシナリオを全マシンで実行する代わりに、シナリオをマシンに
  振り分けます。振り分けは、過去の実行にかかった時間から見積もります。
- `--junit <パス>` を付けると、全マシンの結果を1つのファイルにまとめます。
  どのマシンの結果かは、各 `<testsuite>` の `hostname` で分かります。

## 別のネットワーク(ルーター越し)のランナー機

ランナー機は、手元と同じ LAN になくても構いません。`ssh <宛先> 'echo ok'` が通る Mac なら
使えます。ネットワーク越しに送るのは run 単位のジョブだけなので、通信に遅延があっても
比較的安定して動きます。

- **開けるのは、手元からランナー機への SSH だけです。** 手元の Mac が外から接続を受ける
  必要はありません。ファイルの転送、進み具合の表示、成果物の回収、ライブ映像は、
  すべてこの SSH 接続の中を通ります。
- **ポート番号や踏み台は `~/.ssh/config` に書きます。** 宛先を `host:2222` のような形では
  書けません(`:` や空白を含む宛先は受け付けません)。`~/.ssh/config` に `Host mac2` /
  `HostName` / `Port` / `ProxyJump` を書いて別名を作り、その別名を宛先に使ってください。
- **SSH のポートをインターネットにそのまま公開しないでください。** VPN(Tailscale など)で
  つなぐ形を想定しています。ポート転送を使う場合は、転送するポートを1つだけにし、接続元の
  IP アドレスを絞り、ランナー機の sshd ではパスワード認証を無効にしてください。
- **画面共有(5900 番ポート)はルーターで開けないでください。** 代わりに
  `ssh -L 5900:localhost:5900 <宛先>` でトンネルを張り、`vnc://localhost:5900` に接続します。
- **回線が細くても、止まらずに機能を落として動きます。** ライブ映像が張れないときは静止画に
  切り替わります。接続が一時的に切れている間、タイルは `unknown` になります。これは
  「状態を確認できていない」という意味で、「空いている」という意味ではありません。
  回線への負荷がいちばん大きいのは録画の回収です。

**ランナー機に実機をつなぐ場合**、手元の Mac とのネットワーク経路は関係ありません。
関係するのはランナー機側の LAN です。USB 接続なら設定は要りません。LAN 経由の iPhone は、
端末が待ち受けて Mac から接続しに行くので、Mac のファイアウォールの設定も要りません。
ただし、次の2つが必要です。

- ランナー機と端末が同じサブネットにいること
- アクセスポイントのクライアント隔離(プライバシーセパレータ)が切ってあること

## VSCode 拡張から使う

拡張には「実行先のマシンを選ぶ」画面はありません。実行プロファイルを選ぶと、
そのマシンプロファイルの `machine` によって実行先も決まります。

拡張でできることは次のとおりです(手順は[リモートランナーのセットアップ](remote_runner_setup_ja.md))。

- **マシンを登録する**: デバイスモニターの「設定」タブの「マシン」の表で登録します。
  CLI の `fleetest remote machines` と同じ登録簿を読み書きします。
- **マシンプロファイルにデバイスを追加する**: 「デバイスを選択」の「マシン:」を切り替えると、
  そのマシンにあるデバイスの一覧が出ます。その場で新しいデバイスを作ることもできます。
  追加したデバイスには、選んだマシン名が `machine` として書き込まれます(手元の Mac なら `"local"`)。
- **版を揃えてから実行する**: 実行を始める前に、ランナー機の fleetest の版が手元と揃っているかを
  確認します。ずれていれば「更新して実行」で揃えられます。

ランナー機への fleetest の導入(`fleetest remote setup`)は、拡張からはできません。ターミナルで行います。

登録したリモートのデバイスは、デバイスモニターで手元のデバイスと同じように表示・操作できます。
状態の表示、ライブ映像、タイルごとの起動・停止も同じです。見た目の違いは、マシン名の
バッジが付くことだけです。ただし、ブリッジやデバイスの状態の自動修復は、手元のデバイスにしか
効きません。

## 1台のランナー機を複数人で使うとき

1台のランナー機では、**同時に1つの実行しか動きません**。デバイスはそのランナー機のものなので、
2つの実行が同じデバイスを取り合わないようにしています。使用中のときは、誰がいつから
使っているかが表示されます。

- **空くまで待つ**: CLI では `--wait-lock <秒>` を付けます。VSCode 拡張では設定
  `fleetest.remoteWaitLock` に秒数を入れます(既定は 0 で、待たずに失敗します)。
  使用中のランナー機を奪う操作は、拡張にはありません。
- **誰が使っているかを見る**: `fleetest remote status --runner <マシン名>` の LOCK 欄に出ます。
  `-` は「確認できなかった」という意味で、「空いている」ではありません。デバイスモニターでは、
  ツールバーのそのマシンの行に 🔒 が出ます。
- **実行中はライブ映像が自動で止まります**: 誰かの実行が始まると、そのマシンのタイルは
  ライブ映像から2秒ごとの静止画に切り替わり、実行が終わると元に戻ります。映像の配信が
  テストの実行を邪魔するためで、自分の実行でも同じです。また、同じデバイスを2人が同時に
  見ているときは、後から開いた人の画面が静止画になります。
- **他の人の実行を壊す操作は止まります**: `fleetest remote clean` は、実行中の run があると
  中止します。拡張で一括停止やデバイスの削除をするときは、確認画面に誰の run が実行中かが
  表示されます。

`~/.config/fleetest/config.json` の `issuerId` に自分の名前を設定しておくと、これらの表示に
その名前が出ます。複数人で使うときのセットアップは、[リモートランナーのセットアップ](remote_runner_setup_ja.md)の
「1台のランナー機を複数人で使うとき」を見てください。
