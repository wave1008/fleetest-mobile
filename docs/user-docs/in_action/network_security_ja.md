# ネットワークの露出とセキュリティ

社内 LAN(インターネットに出さない企業内ネットワーク)で運用する受け手が、情シス/セキュリティ
担当に「このツールは何をどこに開くのか」を説明するための要点です。導入の手順書ではありません。

## 待ち受け(listen)の一覧

| 何 | どこに開くか | 認証 |
|---|---|---|
| 手元の Mac(CLI・MCP サーバ・モニター・ライブ操作) | **ポートを1つも開かない**。すべて標準入出力の NDJSON で親子プロセス間だけ | — |
| iOS Simulator のブリッジ(XCUITest / in-app) | デバイス内の `127.0.0.1` のみ。Simulator はホストとネットワークスタックを共有するので手元から届く | 不要(ループバック) |
| Android のブリッジ(実機・エミュレータ共通) | **デバイス内のループバックのみ**。手元へは `adb forward` が張る動的なローカルポート経由 | 不要(ループバック) |
| Android エミュレータの gRPC | `127.0.0.1` | エミュレータ自身が発行するブート毎の Bearer トークン |
| **iOS 実機・USB 経路(既定・推奨)** | iproxy(libimobiledevice)の USB トンネル。**すべてループバックに留まる** | 不要(ループバック) |
| **iOS 実機・LAN 経路** | **端末の全インターフェース**。同じ LAN から届く | **トークン必須**(下記) |

- ブリッジのポートは **8123〜8154 の 32 本**(iOS)。
- **iOS 実機で LAN 経路が選ばれる条件は2つ**: ①その Mac に iproxy が入っていない ②端末が USB で
  なく Wi-Fi で繋がっている。どちらかに当てはまると自動で LAN になります。
- **in-app ブリッジは製品ビルドに混入しません**。アプリ起動時に `DYLD_INSERT_LIBRARIES` で
  差し込むだけで、アプリのバイナリにリンクされません。

## LAN 経路のトークン認証(ブリッジ版 91 以降)

- ブリッジを起動するたびにホストが **32 バイトの乱数**を作り、テストランナーの環境変数として
  渡します。
- 手元からの要求は毎回 `X-FT-Token` ヘッダで送ります。**一致しなければ 401** を返し、端末には
  一切触れません。比較は定数時間です。
- **トークンが無いまま全インターフェースに開くことはできません**(ランナーが起動を拒否します)。
- トークンは `<プロジェクト>/.fleetest/bridge-<ポート>.endpoint` に置かれ、**引数や環境変数で
  他のプロセスへ渡りません**(`ps` で見えないようにするためです)。
- **これは同じ LAN 上の第三者を防ぐためのものです**。ループバックの経路には認証が無く、その
  Mac にログインできる人は元から同じことができます。

## 外向きの通信

- **テレメトリ・解析データの送信は一切ありません**(製品コードに外部 URL が1つもありません)。
- 出ていくのは **GitHub への HTTPS だけ**で、導入と更新のとき(`git clone` / `git ls-remote` /
  起動スクリプトの取得)です。**完全な閉域網では社内ミラーが必要です。**
- Apple Intelligence(Foundation Models)は**端末内で動きます**。外へは出ません。
- **テスト対象アプリを Google へ送りません。** Android の `adb install` は Play Protect の照会で
  止まることがあるため、インストールの間だけ検証を切って必ず元に戻します。

## リモートランナー(別の Mac へ実行を投げる場合)

- 経路は **SSH のみ**(鍵認証)です。パスワード入力は行わず、**ホスト鍵の検証を緩める設定は
  一切使いません**。
- リモートへ渡す引数はすべてクォートされます。
- **信頼モデル**: ランナー機そのものは信頼します(SSH で入れる = そのユーザーとして任意の
  コードを実行できる関係です)。一方、**ランナーが返してくる中身は外部入力として扱います**。
- ランナーには鍵・ソース・シナリオ・レポート・**録画**が載ります。**録画やスクリーンショットには
  テストで入力した資格情報が写り込みます。** 共有ラボでは他の利用者も読めるため、本番の資格情報を
  シナリオやプロファイルに置かないでください。
- 到達性(ルーター越し・ファイアウォール・アクセスポイントのクライアント隔離)は別ページ
  [リモートランナー](remote_runners_ja.md)を参照してください(ここでは繰り返しません)。

## 運用側で決めること

1. **実機 iPhone を使うすべての Mac に `brew install libimobiledevice` を入れる。** USB
   トンネルになり LAN への露出が無くなります。実測では1往復が約 48ms から約 5ms になり、
   実機のシナリオが約 25% 速くなるという結果もあり、こちらが本来の既定です。
2. Wi-Fi 接続の実機をどうしても使うなら、**テスト用の端末とランナー機をセグメント分けした
   VLAN に置く**。
3. 閉域網なら **GitHub の社内ミラー**を用意する(無いと導入も更新もできません)。
4. **本番の資格情報をシナリオ・プロファイルに書かない。**
