# Troubleshooting

Common problems and how to resolve them.

| Symptom | Check | Fix |
|---|---|---|
| On-device model unavailable | Is Apple Intelligence enabled in System Settings? **Is the Mac's system language English?** | Enable it (`fleetest doctor` shows the reason it's unavailable). Under `ja-JP` the pane does not appear at all and every call fails while `availability` still says available — confirm with `fleetest doctor --fm-only`, which really infers. FM is experimental and English-only during 2026 ([environments.md](../overview/environments.md)). This only blocks self-healing, `screenLooksLike`, and failure triage — everything else runs without it |
| Cannot connect to the driver | iOS: is a bridge running? Android: is the device visible to `adb devices`? | iOS: run `fleetest bridge up` first (its log is `.fleetest/bridge-<port>.log`). Android: reconnect the device/emulator so it shows up in `adb devices` |
| Scenario fails to run due to a compile error | Run `swift build --product fleetest-scenarios-<project>` and read the error | Fix the reported error. A scenario generated by live-control recording that fails to compile is automatically quarantined into `scenarios/_disabled/` rather than blocking the rest of the project |
| Project isn't recognized (after a manual copy or `git pull`) | Does `fleetest project list` warn about an unregistered project? | Run `fleetest project sync` to regenerate the marker section in `Package.swift` |
| "Machine profile not found" | Does the run profile's `"machine"` match a file name under `profiles/machines/`? | Fix the name so it matches `profiles/machines/<name>.json` exactly |
| Android snapshot is slow | Check `fleetest bridge status --platform android` and `fleetest doctor` for the bridge's install/running state | Run `fleetest bridge up --platform android` to force a re-setup of the resident bridge |
| Japanese (or other non-ASCII) text doesn't get typed on Android | The bridge normally types via `ACTION_SET_TEXT`, so no IME switching is needed | Check the bridge's install state with `fleetest doctor`; reinstalling the bridge (`fleetest bridge up --platform android`) usually resolves it |

If none of this resolves the issue, ask your agent (Claude Code or Codex) to investigate — it can read bridge/run logs
and the failure report directly.
