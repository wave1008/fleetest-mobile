# 更新

[in English](update.md)

fleetest の更新は、**VSCode 拡張の通知から行う**のが基本です。新しいリリースが出ると拡張が知らせ、
デバイスモニターの「設定」タブで更新できます。AIアシスタントに頼む・ターミナルで更新スクリプトを実行する、
という方法もあります(下の「他の方法」)。

更新で入るのは fleetest の**最新のリリース**です。

## 1. 通知を受ける

VSCode の起動時に、拡張が新しいリリースの有無を確かめます(1日1回まで)。あれば右下に通知が出ます。

```
新しいリリース X.Y.Z があります(現在 A.B.C)。デバイスモニターの「設定」タブから更新できます。
[設定タブを開く] [変更内容] [この版は通知しない]
```

- **変更内容**: そのリリースで何が変わったかを読めます。
- **この版は通知しない**: その版については通知を止めます(次の版が出ればまた通知します)。
- 通知を待たずに確かめたいときは、コマンドパレットの `fleetest: 更新を確認` か、「設定」タブの「更新」にある「更新を確認」を押します。

## 2. 「設定」タブで更新する

通知の「設定タブを開く」を押す(またはステータスバーの **fleetest mobile** → 「設定」タブ)と、「更新」の欄に
今の版と新しい版が並びます。「更新する」を押します。

```
fleetest を更新します。git pull・再ビルド・拡張の再インストールを行い、数分かかります。続けますか?
[更新する]
```

「更新する」を押すと、進捗の通知「fleetest を更新しています」が出て、進み具合が OUTPUT パネルの `fleetest` に
1行ずつ流れます。fleetest 本体の取得・ビルド・VSCode 拡張の入れ直し・テストプロジェクトの再整合まで、まとめて行います。
途中で止める操作はありません(途中で止めると、取得だけ済んでビルドが終わっていない状態が残るためです)。

## 3. ウィンドウを再読み込みする

終わると、確認が出ます。

```
fleetest の更新が完了しました。反映するにはウィンドウを再読み込みしてください。
[再読み込み]
```

「再読み込み」を押します。**入れ替えた拡張は再読み込みまで有効になりません**(押さなかったときは、あとで
コマンドパレットの `Developer: Reload Window` を実行します)。

更新に失敗したときは、「fleetest の更新に失敗しました(終了コード N)」と出ます。OUTPUT パネルの `fleetest` にある
`[fail]` の行を見てください。ログは `<作業フォルダ>/.fleetest/install-*.log` にも残ります。

## 4. 更新したあとにすること

- **AIアシスタントを再起動する**: 新しい版の手順書(スキル)は、再起動のあとに読まれます。
- **ランナー機も同じ版に揃える**: リモート実行を使っているときは、ランナー機も手元と同じ版にします。揃っていないと
  テストは始まりません(実行の前に拡張が確かめ、「更新して実行」で揃えられます)。手順は
  [Mac を追加する](fleet/adding_mac_ja.md)の「fleetest を更新したとき」にあります。

## 他の方法

### AIへの指示文

```text
fleetest を最新にして。
```

更新の有無だけ知りたいときは「fleetest の更新はある?」と聞きます(クローンは変更しません)。
更新のあとの再読み込み(ステップ 3)は同じように必要です。

<details>
<summary><b>手動で実行する場合(クリックで詳細表示)</b></summary>

作業フォルダ(`TestProjects/` があるフォルダ)で、fleetest のクローンにある更新スクリプトを実行します。
拡張の「更新する」が実行しているのも、このスクリプトです。

```bash
bash ../fleetest-mobile/Scripts/update.sh
```

- 更新が無ければ「Up to date」と表示して何もせずに終わります。壊れた導入を入れ直したいときだけ `--force` を付けます。
- クローンが作業フォルダの隣の `fleetest-mobile` ではないときは `--tool-root <クローンのパス>`、作業フォルダが
  カレントでないときは `--work-dir <作業フォルダ>` を付けます。

</details>
<br>

## 閉域網で更新する

インターネットに出られない環境では、`bash <クローン>/Scripts/update.sh` を直接実行します。GitHub 宛てを社内ミラーへ向ける設定は
[ネットワークの露出とセキュリティ](security/network_security_ja.md)にあります。
