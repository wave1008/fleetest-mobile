# リモート実行

[in English](remote_runners.md)

テストを別の Mac(ランナー機)で実行する手順です。手元の Mac から SSH で run を送り、ランナー機でふつうに実行して、
出力と成果物(レポート・録画・ログ)を手元へ持ち帰ります。

できること・全体像・マシン名・どのマシンで実行するかが決まる仕組みは、[フリートの考え方](concepts_ja.md)にあります。

## 前提

ランナー機の用意が済んでいること。済んでいなければ、先に[Mac を追加する](adding_mac_ja.md)を終えてください
(ランナー機の準備・SSH・マシンの登録・ランナー機への fleetest の導入・つながるかの確認まで)。

Claude Code では、`/fleetest-remote-setup` スキルでもセットアップできます。
スキルは必要なことを質問し、機械的な作業は `fleetest remote setup` に任せ、人の手が要る作業は
あなたに渡して、最後に結果を報告します。ランナー機の準備のように sudo や画面操作が要る作業は、
スキルは代わりに行いません。

## 1. 実行プロファイルにランナー機のデバイスを入れる

どのマシンで実行するかは、実行プロファイルの `devices` に書いた `machine` で決まります
([フリートの考え方](concepts_ja.md)の「どこで実行されるかは実行プロファイルで決まる」)。

### AIへの指示文

```text
M1Max にあるデバイスを調べて、実行プロファイル ios-run に追加して。
```

<details>
<summary><b>手動で実行する場合(クリックで詳細表示)</b></summary>

VSCode 拡張では、実行プロファイルの「デバイスを追加」ボタンから「デバイスを選択」を開き、「マシン:」を
切り替えます。CLI では、`fleetest remote exec M1Max -- api installed-devices` でランナー機のデバイスを調べて、
実行プロファイルの `devices` に `machine` を付けて書きます。どちらも手順は
[Mac を追加する](adding_mac_ja.md)のステップ4にあります。

</details>
<br>

## 2. 回す

実行プロファイルのデバイスがランナー機に載っていれば、ふだんの実行と同じ指示で、ランナー機で実行されます。
`--runner` を付ける必要はありません。

### AIへの指示文

```text
実行プロファイル ios-run で、シナリオ <シナリオ名> を実行して。
```

この1回だけ別のマシンで実行したいときは、マシン名を添えます。

```text
実行プロファイル ios-run で、シナリオ <シナリオ名> を M1Max で実行して。
```

<details>
<summary><b>手動で実行する場合(クリックで詳細表示)</b></summary>

```bash
fleetest run --profile <実行プロファイル> --scenario <シナリオID>                  # プロファイルのデバイスの machine に従う
fleetest run --runner <名前> --profile <実行プロファイル>        # この回だけ特定のマシンへ送る
fleetest run --project <プロジェクト> --fleet <名前>             # フリートの全マシンで同じシナリオを実行する
fleetest run --project <プロジェクト> --fleet <名前> --split      # シナリオを全マシンに振り分けて実行する
```

フリートは、マシンと実行プロファイルの組を並べたものです。
`TestProjects/<プロジェクト>/profiles/fleets/<名前>.json` に、`host`(マシン名)と
`profile`(実行プロファイル名)の組を `runs` に並べて定義します。手元の Mac は `"local"` と書きます。
フリート定義での実行は CLI だけ(拡張・MCP からは実行できません)で、試験的な機能です。

```jsonc
// profiles/fleets/two-runners.json
{ "runs": [
    { "host": "M1Max",   "profile": "ios-run" },
    { "host": "M2Ultra", "profile": "ios-run" } ] }
```

フリート定義ではマシン名を `host` キーに書きます(実行プロファイルのデバイスの `machine` とはキー名が違います)。

- `--split` を付けると、同じシナリオを全マシンで実行する代わりに、シナリオをマシンに
  振り分けます。振り分けは、過去の実行にかかった時間から見積もります。
- `--junit <パス>` を付けると、全マシンの結果を1つのファイルにまとめます。
  どのマシンの結果かは、各 `<testsuite>` の `hostname` で分かります。

</details>
<br>

初回はランナー機でシナリオのビルドなどがあるので、始まるまで数分かかります。2回目からは数秒で始まります。

## 3. VSCode 拡張から使う

拡張には「実行先のマシンを選ぶ」画面はありません。実行プロファイルを選ぶと、
そのデバイスが持つ `machine` によって実行先も決まります。

拡張でできることは次のとおりです(手順は[Mac を追加する](adding_mac_ja.md))。

- **マシンを登録する**: デバイスモニターの「設定」タブの「マシン」の表で登録します。
  CLI の `fleetest remote machines` と同じ登録簿を読み書きします。
- **実行プロファイルにデバイスを追加する**: 実行プロファイルの「デバイスを追加」ボタンから
  「デバイスを選択」を開き、「マシン:」を切り替えると、そのマシンにあるデバイスの一覧が出ます。
  その場で新しいデバイスを作ることもできます。追加したデバイスには、選んだマシン名が
  `machine` として書き込まれます(手元の Mac なら `"local"`)。
- **版を揃えてから実行する**: 実行を始める前に、ランナー機の fleetest の版が手元と揃っているかを
  確認します。ずれていれば「更新して実行」で揃えられます。

ランナー機への fleetest の導入(`fleetest remote setup`)は、拡張からはできません。ターミナルで行います。

登録したリモートのデバイスは、デバイスモニターで手元のデバイスと同じように表示・操作できます。
状態の表示、ライブ映像、タイルごとの起動・停止も同じです。見た目の違いは、マシン名の
バッジが付くことだけです。ブリッジの自動修復はリモートのデバイスも対象ですが、デバイスの健全性
(Wi-Fi の修復)の監視は手元のデバイスにしか効きません。実機はどちらも対象外です。

`scripts/compose.yaml` のサービスはランナー機の上で起動するので、ランナー機にもコンテナランタイムと
イメージが要ります([Mac を追加する](adding_mac_ja.md)の前提の表)。

## 4. 1台のランナー機を複数人で使うとき

他の人の実行が走っているランナー機へ実行を送ると、空くまで待ちます。待っている様子は、実行ログに自分の順番として出ます。

### AIへの指示文

```text
実行プロファイル ios-run で、シナリオ <シナリオ名> を M1Max で実行して。M1Max が使用中なら、最大10分まで順番を待って。
```

<details>
<summary><b>手動で実行する場合(クリックで詳細表示)</b></summary>

```bash
fleetest run --runner M1Max --profile <実行プロファイル> --scenario <シナリオID> --wait-lock 600
```

`--wait-lock <秒>` は、空くまで待つ上限です。待っている間は、実行ログに自分の順番が出ます。
複数のマシンにまたがる実行では、この上限は待ち全体(この Mac のロック・この Mac のデバイス・各ランナー機の合計)にかかります。この Mac のデバイスが空くのを待っているときも、実行ログに出ます。

</details>
<br>

1台のランナー機では、**同時に1つの実行しか動きません**。デバイスはそのランナー機のものなので、
2つの実行が同じデバイスを取り合わないようにしています。使用中のときは、誰がいつから
使っているかが表示されます。手元の Mac で起動する実行も同じです
([並列実行](../reference/running/parallel_execution_ja.md)参照)。

- **空くまで待つ**: **拡張から**の実行は既定で最大 1 時間待ちます(先に並んでいる run が数本あっても待ち切れる長さです)。
  秒数はデバイスモニターの「**設定**」タブ →「**マシン**」→「**ランナー競合時の
  最大待機時間**」で変えられます(0 にすると待たずに失敗します)。設定キーは
  `fleetest.remoteWaitLock` です。**CLI** は既定では待たずに失敗するので、`--wait-lock <秒>` を付けます。
  並んでいる間は、実行ログに自分の順番が出ます。使用中のランナー機を奪う操作は、拡張にはありません。
- **誰が使っているかを見る**: `fleetest remote status --runner <マシン名>` の LOCK 欄に出ます。
  `-` は「確認できなかった」という意味で、「空いている」ではありません。デバイスモニターでは、
  ツールバーのそのマシンの行に 🔒 が出ます。
- **他の人の実行中はライブ映像が自動で止まります**: 他の人の実行が始まると、そのマシンのタイルは
  ライブ映像から静止画に切り替わり、実行が終わると元に戻ります。映像の配信が
  テストの実行を邪魔するためです。状態を観測できないマシンも同じです。自分の実行では、
  デバイスモニターの「ライブ更新」(既定オン)がオンなら配信を続けます。また、同じデバイスを2人が同時に
  見ているときは、後から開いた人の画面が静止画になります。
- **他の人の実行を壊す操作は止まります**: `fleetest remote clean` は、実行中の run があると
  中止します(`--ignore-lock` で押し切れますが、その run を殺します)。拡張で一括停止やデバイスの削除をするときは、確認画面に誰の run が実行中かが
  表示されます。
- **死んだロックを外す**: ディスパッチが異常終了してロックだけが残ったときは、
  `fleetest remote unlock [--runner <マシン名>|local] [--force]` で回収します。外せるのは自分のロックだけで、
  `--force` を付けると持ち主を問わず外します(その run がまだ動いていれば壊れます)。

`~/.config/fleetest/config.json` の `issuerId` に自分の名前を設定しておくと、これらの表示に
その名前が出ます。複数人で使うときのセットアップは、[Mac を追加する](adding_mac_ja.md)の
「1台のランナー機を複数人で使うとき」を見てください。

## 知っておくこと

### 別のネットワーク(ルーター越し)のランナー機

ランナー機は、手元と同じ LAN になくても構いません。`ssh <宛先> 'echo ok'` が通る Mac なら
使えます。ネットワーク越しに送るのは run 単位のジョブだけなので、通信に遅延があっても
比較的安定して動きます。

- **開けるのは、手元からランナー機への SSH だけです。** 手元の Mac が外から接続を受ける
  必要はありません。ファイルの転送、進み具合の表示、成果物の回収、ライブ映像は、
  すべてこの SSH 接続の中を通ります。
- **ポート番号や踏み台は `~/.ssh/config` に書きます。** 宛先を `host:2222` のような形では
  書けません(`:` や空白を含む宛先は受け付けません)。`~/.ssh/config` に `Host mac2` /
  `HostName` / `Port` / `ProxyJump` を書いて別名を作り、その別名を宛先に使ってください。
- **SSH のポートをインターネットにそのまま公開しないでください。** VPN(Tailscale など)で
  つなぐ形を想定しています。ポート転送を使う場合は、転送するポートを1つだけにし、接続元の
  IP アドレスを絞り、ランナー機の sshd ではパスワード認証を無効にしてください。
- **画面共有(5900 番ポート)はルーターで開けないでください。** 代わりに
  `ssh -L 5900:localhost:5900 <宛先>` でトンネルを張り、`vnc://localhost:5900` に接続します。
- **回線が細くても、止まらずに機能を落として動きます。** ライブ映像が張れないときは静止画に
  切り替わります。接続が一時的に切れている間、タイルは `unknown` になります。これは
  「状態を確認できていない」という意味で、「空いている」という意味ではありません。
  回線への負荷がいちばん大きいのは録画の回収です。

**ランナー機に実機をつなぐ場合**、手元の Mac とのネットワーク経路は関係ありません。
関係するのはランナー機側の LAN です。USB 接続なら設定は要りません。LAN 経由の iPhone は、
端末が待ち受けて Mac から接続しに行くので、Mac のファイアウォールの設定も要りません。
ただし、次の2つが必要です。

- ランナー機と端末が同じサブネットにいること
- アクセスポイントのクライアント隔離(プライバシーセパレータ)が切ってあること

### ランナー機の保守

ランナー機の結果・レポート・録画は、手元と違って誰も見ていないので、気付かないうちに溜まります。
ときどき `fleetest remote clean --runner <マシン名>` を実行してください。空き容量は `fleetest remote status --runner <マシン名>`(`--runner` は必須)で
確かめられます。`remote clean` は 7 日より古い結果・レポート・録画を消します(`--keep-days <日>` で変えられます。
成果物は実行のたびに手元へ回収済みです)。テストが走っているときは、`remote clean` は止まります(`--ignore-lock` で押し切れますが、その run を殺します)。

手元の fleetest を更新したら、ランナー機も同じ版に揃えます([Mac を追加する](adding_mac_ja.md)の「fleetest を更新したとき」)。

### 安全に使うために

- 経路は **SSH のみ**(鍵認証)です。パスワード入力は行わず、**ホスト鍵の検証を緩める設定は
  一切使いません**。
- リモートへ渡す引数はすべてクォートされます。
- **信頼モデル**: ランナー機そのものは信頼します(SSH で入れる = そのユーザーとして任意の
  コードを実行できる関係です)。一方、**ランナーが返してくる中身は外部入力として扱います**。
- ランナーには鍵・ソース・シナリオ・レポート・**録画**が載ります。**録画やスクリーンショットには
  テストで入力した資格情報が写り込みます。** 共有ラボでは他の利用者も読めるため、本番の資格情報を
  シナリオやプロファイルに置かないでください。
- ルーター越しに使うときの注意は、上の「別のネットワーク(ルーター越し)のランナー機」にあります。
