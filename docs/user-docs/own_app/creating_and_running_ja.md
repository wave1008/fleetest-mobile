# テストを作って回す

[in English](creating_and_running.md)

自分のアプリ(例: テストプロジェクト myshop)の基本ルートのテストを作り、実行し、スモークを選びます。

## 1. テストを作る

### AIへの指示文

```text
fleetest のテストプロジェクト <名前> で、自分のアプリの基本ルート(正常に進む流れ)のテストを1本作成して。<画面や操作の流れ>を行い、<何が見えたら成功か>を確かめて。
このアプリは起動直後に「<ダイアログの名前>」が出ることがある。「<閉じるボタンの文言>」で閉じられるので、出たら閉じてから進むようにして。
```

出たり出なかったりする画面(初回の案内・お知らせ・OS の許可ダイアログ)は、名前と閉じるボタンの文言を入れます。画面が切り替わったかを確かめたいときは、切り替わった先にだけ出る文言を成功の条件に書きます。

## 2. 実行する前に

注文・送信・登録のような取り消せない操作を含むテストは、1回の実行の中で2回行われることがあります。先に洗い出し、テスト用の相手(決済のテストモード・ステージング)に向けてから実行します。

### AIへの指示文

```text
fleetest のテストプロジェクト myshop のシナリオのうち、送信・購入・登録のような取り消せない操作を含むものを洗い出し、
テスト用の決済・ステージングのサーバーに向いているか確認して。
```

## 3. スモークを選ぶ

スモークには、アプリの主要な導線(起動できる・ログインできる・主な画面が開く)を数本だけ選びます。どれを選ぶかは AIアシスタントに相談できます。
フォルダの分け方と回し方は[スモークと回帰を分けて回す](../tutorial/smoke_and_regression_ja.md)にあります。
