# VSCode 拡張

[in English](vscode_extension.md)

`vscode-fleetest` 拡張は、シナリオを VSCode の Test Explorer に表示し、その周りにデバイス操作・
ライブ確認・結果レビューの機能を追加します。ターミナルと同じ `fleetest` CLI を spawn して動くため、
挙動は CLI・MCP と同じになります。

## Test Explorer

シナリオは `TestProjects/<project>/scenarios/**/*.swift` から構成される
folder → class → `@Test` メソッドの3階層ツリーとして Testing ビューに表示されます。対象の
`<project>` は `fleetest.project` 設定で選びます。空のときは自動判定で、拡張は起動時に
`TestProjects/project1/` が無ければ `fleetest project create project1` で作成し、これを初期選択にします
([テストプロジェクトの作成](../project/creating_project_ja.md))。各テスト項目は
3つの方法で実行できます。

- **実行** — デバイス上でシナリオを実行します。
- **実行 (dry-run)** — デバイス不要でシナリオを検証します(セレクタの構文誤り・到達しない
  scene・アサーションの無い expectation・保存済みスナップショットに実在しない `#id` など)。
- **デバッグ** — DAP(Debug Adapter Protocol)アダプタ経由で実行します。`action { }` ブロック内の
  コマンド行にブレークポイントを設定し、デバッグツールバーでステップオーバー・続行・停止ができます。

`fleetest.profile` を設定すると、実行・実行(dry-run)・デバッグはいずれも生の
`fleetest.platform`/`fleetest.port`/`fleetest.serial` ではなく `fleetest api run --profile <name>`
経由になります。デバイスの供給(起動していない Simulator / Emulator は起動します。物理端末は起動できないので、
つないで準備しておきます)とアプリの自動インストールは実行プロファイル側が行います。dry-run はデバイス不要です。

**実行とデバッグには実行プロファイルが必要です**(dry-run は不要)。未選択のまま実行すると、プロジェクトに
実行プロファイルが1つだけならそれを選んで `fleetest.profile` に保存し、そのまま実行します。2つ以上あるときは
実行せず、「実行プロファイルを選ぶ」ボタン付きのエラーを出します。

## ステップ一覧

読み取り専用の **fleetest ステップ** TreeView(Testing ビューコンテナ内)がカーソル位置に追従します。
`@Test` メソッドの本体内にカーソルを置くと、そのシナリオの `scene` グループとステップの一覧が
表示されます。ステップをクリックすると対応するソース行にジャンプします。シナリオの右クリック
メニュー(「fleetest: ステップ一覧を表示」)からも開けます。

## デバイスモニター

コマンド **「fleetest: デバイスモニターを表示」** を実行するか、VSCode 左下のステータスバーの
**fleetest mobile** をクリックすると、デバイスタイルの一覧を表示する
Webview パネルが開きます(1ワークスペースにつき1枚)。各タイルにはデバイス名・プラットフォーム
バッジ(iOS/Android)・状態バッジ・現在の画面が表示され、画面は既定でヘッドレス映像ストリーミング
(`fleetest-simstream`/`fleetest-androidstream`)によりほぼリアルタイムに更新されます
(ストリーミングが使えない場合は定期的なスクリーンショット取得にフォールバックします)。
設定タブの **「ポーリングモードを使用する」** をオンにすると、ストリーミングをやめて従来のポーリング
(一定間隔のスクリーンショット取得)に切り替えられます(ワークスペースごとに記憶されます)。

- 状態バッジ: **接続済み**(緑) — ブリッジ接続済みで操作可能 / **起動中**(黄) — デバイスは
  起動しているがブリッジ未接続 / **未起動**(灰) — デバイス停止中。
- タイルを右クリックするとそのデバイス1台だけを起動/停止できます
  (`fleetest api start-device`/`stop-device`)。デバイス操作は共有の1本のキューで1件ずつ実行される
  ため、順番待ちのタイルには「待機中...」バッジが表示されます。
- ツールバーのボタンで表示中の全デバイスの起動/停止、モニタープロセスの再起動ができます。
- ツールバーのグラフ(MEM / CPU / GPU / Vision / FM)は Mac の負荷と、画像判定(Vision)・Foundation Models(FM)の
  呼び出し回数です。FM が使えない状態になると、FM のグラフが灰色になり右に **N/A** と出ます
  (カーソルを置くと、止まった経路と理由・観測時刻が出ます)。この間は FM を使う検証(`screenLooksLike`・
  テキストの可視性検証の FM 段)が働かないことがあります。
  この Mac のハードウェアビデオエンコーダーが使えないときは、その右に **⚠︎AVE** と出ます
  (録画の切り出しはソフトウェアで続けるため遅くなります。カーソルを置くと理由と観測時刻が出ます)。
  OCR を使ったテキストの可視性検証(`ocrTextVisibilityCheck`)が有効な run だけ、OCR モデルをコンパイルしている間(ビルドし直した直後の最初の run 等。数十秒)は、run は最初のシナリオを始めずに
  コンパイルの完了を待ちます(実行中の欄に「Vision コンパイル中」と出ます)。
  設定タブの「マシン」にある **「デバイスモニターにメモリ容量、CPUコア数、GPUコア数を表示する」**
  (既定 OFF)を ON にすると、名札が `MEM 192`(GB)/ `CPU 24` / `GPU 76` のようにマシンごとの容量付きになります
  (値が届くまでは `MEM -`)。
- ツールバーの下の **run ボード**には、この Mac と登録したランナー機が**1台1行**で並び、
  **いま走っている実行**はそのマシンの行に「何本中何本」「残り何分」つきで出ます(自分が起こした
  実行に限らず、CLI や別の人の実行も出ます)。走り出す前は本数の代わりに、いま何をしているか
  (「シナリオをビルド中」「デバイスの準備を開始します」「ランナーをビルド中」「デバイスを起動中」「ブリッジを起動中」
  「デバイスを設定しています」「アプリをインストール中」「テストを開始しています」)が出ます。
  動画を録画した実行では、全シナリオの後に動画を切り出している間、残りの代わりに「動画を編集中 12/48」
  (切り出し終えた本数/全本数)が出ます。
  行を開くとそのマシンのデバイスが並び、行をクリックするとそのマシンのデバイスがラインビューで選択されます。
- 「デバイスモニター」タブは上から **ラインビュー**(デバイスタイルの並び)・**グリッドビュー**
  (選択したデバイスの画面の拡大表示)・**実行ログビュー**(選択したデバイスの実行ログ)の3つに分かれます。
  境界線のドラッグで高さを、見出し行のクリックで開閉を変えられます(どの高さにしても見出し行は残ります)。
- グリッドビューと実行ログビューに出るのは**ラインビューで選択したデバイスだけ**です。タイルはどこを
  押しても選択の入り切りが変わり、タイルの外側を押すと選択が全部外れます。1台も選んでいないときは
  どちらのビューにも「デバイスを選択して下さい」と出ます(実行中の供給の進行は実行ログビューに出ます)。
  ちょうど1台だけ選んだときは、拡大表示の右隣のカラムに **戻る・ホーム・タスク切替・拡大・縮小** のボタンが縦に並び、そのデバイスをその場で操作できます
  (**戻る** は1台だけの表示を抜けます。「このデバイスのみ選択」の前の選択に戻し、前の選択が無ければ選択を解除します)。
  画面の上では **クリックでタップ**、**Command(⌘)+クリックでダブルタップ**、**500ms 以上押し続けて長押し**、
  **ドラッグでスワイプ**、**Option(⌥)+ドラッグで指の軌跡どおりになぞる**操作ができます(Command を押している間は
  「ダブルタップ」、Option を押している間は「軌跡」が点き、押し続けるとその説明が出ます)。拡大表示の右には **要素一覧**(「更新」で取り直し・
  見出しの台数の右の「バウンディングボックスを表示」で画面に枠を重ねる・長い行は横にスクロール)と **操作記録** が並び、
  拡大表示の画面のすぐ下に **入力するテキスト**(Enter で送信)があります。
  選んだだけではデバイスへつながないので、要素一覧は最初の操作か「更新」で表示されます(「バウンディングボックスを表示」がオンなら開いた時点で表示されます。このスイッチはパネルを開くたびにオフから始まります)。
  操作記録はデバイスごとに分かれます。操作記録の右の列には、その操作をシナリオに書くときの DSL の1行が出て、
  クリックでコピーできます。画面のボタンなど操作できる要素を押したときはセレクタの行(`tap("#login")` など)になり、
  操作の列にもそのセレクタが添えられます(`タップ: ログイン("#login")`)。地図のような操作できない要素を押したときは、その要素のセレクタの行に
  押した点がコメントで付きます(セレクタの形は要素の中心を押すので、押した点とずれることがあります)。
  これは安定したセレクタが書けて、要素の中心に他の物が無いときだけです。それ以外(中央にボタンがある領域の余白を押したとき等)は
  座標の行になり、行末にセレクタへの置き換えを促すコメントが付きます。
  画面の上のダブルクリックは2回のタップになるので、選択の切り替えは画面の外側(デバイス名の段や余白)を
  ダブルクリックします。折りたたみの端末(iPhone Duo の Simulator・折りたたみの Android Emulator)では
  **折りたたむ・開く** のボタンも出ます(実機には出ません)。操作は選択したデバイスの常駐プロセスへ送ります。
  別のデバイスを選び直したときは、そのデバイスへつなぎ替えてから操作します。
- デバイスがテストを実行している間も操作できます。操作はテストの実行と干渉するので、
  あなたの判断で行ってください。その操作は、そのとき実行中だったシナリオの結果に記録され、ダッシュボードの
  「人の操作」とレポートに出ます(入力した文字列は記録されません)。シナリオとシナリオの間の操作はどちらにも
  属さないので、結果には出ません。
- ラインビューの見出し行(「ライブ更新」の右)にある **iOS** / **Android** のバッジ(既定は両方オン)で、4つのセクション
  (実行中・デバイス一覧・選択したデバイス・実行ログ)に出すデバイスをプラットフォームで絞れます。バッジはそれぞれ
  独立して切り替わり、両方をオフにはできません(オンの側が1つだけのときに押すと、もう片方と入れ替わります)。
  デバイス自体は止まりません(表示だけ)。
- ラインビューの見出し行にある **「ライブ更新」** を OFF にすると、全デバイスの画面の配信と
  取り込みを止めて Mac の負荷を下げます。タイルは最後の画面のまま暗く表示されます
  (状態の表示は更新が続きます)。
- **「テストセッション」タブ**では終わった実行を一覧から開き、シナリオごとの動画・ステップのツリー・エラー一覧を
  見られます。録画しなかった実行(実行プロファイルの `record: false`)も「録画なし」の印付きで並び、
  ステップのツリーとエラー一覧を見られます。**「デバイスモニター」タブを表示したまま実行が終わると**、
  録画の準備ができた時点で自動的に「テストセッション」タブへ切り替わり、その実行の録画が開きます(他のタブを
  表示しているときは切り替えません。録画の無い実行・キャンセルした実行も切り替えません)。
  テストが全部終わってから切り替わるまでの間は、「テストを実行」ボタンの右に「録画を編集中...」と表示されます。
  再生ビューのヘッダーにある **「テスト結果をエクスポート」** ボタンで、開いているセッションの結果を
  Excel(.xlsx)ファイルへ書き出せます。保存先はダイアログで選べます。
- **「プロファイル」タブ**ではテストプロジェクト自体の一覧・作成・コピー・名前変更・削除と、
  実行/アプリプロファイルの一覧・作成・コピー・名前変更・削除・編集ができます。実行プロファイルの
  節には全実行プロファイルのデバイスの和集合がチェックボックス付きで並び(チェック済み=その
  プロファイルが走らせる)、「デバイスを追加」ボタンもここにあります。アプリプロファイルの
  **「対象 OS」**(iOS / Android / ハイブリッド)を選ぶと、選ばなかった OS の欄が隠れます。実行プロファイルは
  参照するアプリの対象 OS を引き継ぎ、その OS のセクションとデバイスだけを表示します。対象外の OS の
  デバイスが登録されていれば、名前を挙げて警告します(JSON からは消さず、実行時は無視されます)。
- **「設定」タブ**には表示・更新・ログと録画のクリーンアップ・リモート実行のマシン登録に関する
  設定があり、下記の更新チェック・更新の実行もここから行います。一番上の **「ツール」** には
  「プロセス」のボタンがあり、押すとそのタブが現れます。
- **「プロセス」タブ**(fleetest の常駐プロセスの一覧と停止)は起動時には
  出ません。開くとタブが現れ、タブの × で閉じられます。
- 画面のどこで右クリックしても、既定の「切り取り/コピー/貼り付け」のメニューは出ません(文字を打つ
  入力欄を除く)。

## ライブ操作

デバイスの画面を直接操作する機能で、デバイスモニターで **1台だけ選択したとき**のグリッドビューにあります(上記)。
選んだだけではデバイスへつながず、最初の操作か「更新」でつなぎます。

対象デバイスのブリッジがまだ起動していない場合は自動で起動します。起動中に操作すると、エラーではなく
「デバイスの準備中です。表示されたら操作してください」という案内が出ます —— 通常は既存のビルドを再利用するため
数十秒程度で、そのデバイス向けの最初のビルドだけ長くかかります。

| 操作 | 動作 |
|---|---|
| クリック | タップ |
| 動かさず約500msホールド | 長押し(500ms を過ぎると始点が橙になり「長押し」と出る。そのまま動かすと長押しからのドラッグ。Command(⌘)を押しているときは出ない = 離せばダブルタップ) |
| ドラッグ | スワイプ(方向は始点終点の差分から自動判定) |
| Option(⌥)+ドラッグ | 指の軌跡どおりになぞる(ツールバーの「軌跡」は Option を押している間だけ点灯する。離さない1本のタッチ。押したまま止まってから動かすと長押しからのドラッグになる(500ms 止まると「長押し」の印が出る。iOS のマップはピンを立ててパンしない)。なぞった時間どおりに再生する。60 秒を超えた時点で中止してエラーを出し、離しても送らない。離した後、デバイスがなぞっている間は、なぞった線が薄くなり、なぞり終えた部分が太い線で伸びていく) |
| Command(⌘)+クリック | ダブルタップ(ツールバーの「ダブルタップ」は Command を押している間だけ点灯する) |
| ツールバーの拡大・縮小 | ピンチ(画面全体) |

iOS の Compose アプリでは、実機と `xcuitest` モードでダブルタップ(Command(⌘)+クリック)が効きません。
拡大したいときはツールバーの拡大(ピンチ)を使ってください([ジェスチャ](../commands/gestures_ja.md))。

画像の横に並ぶ要素一覧は読むためのもので、行をクリックしてもデバイスは操作されません。行にマウスを
乗せると、画像の上でその要素の枠が光ります。テキスト入力欄は、デバイス側でフォーカスしている要素へ
入力を送ります(先に画像の上で入力欄をタップしてください)。

操作のあと、画面が止まるのを待って要素の木を自動で取り直し、枠を描き直します(テストの実行中は取り直しません)。

対象アプリが前面から外れても操作は続けられます(iOS)。ホーム画面・アプリスイッチャー・別のアプリ・
システムダイアログが前面になると、画面に映っているものをそのまま触れるように切り替わり、要素一覧も
そちらに変わります。対象アプリが前面に戻れば自動で元に戻ります(戻らないときはアプリを起動し直してください)。

## 結果ダッシュボード

コマンド **「fleetest: 結果ダッシュボードを開く」** を実行すると、デバイスモニターの **「ダッシュボード」タブ**に
プロジェクトの `fleetest api results` の集計が表示されます。上から順に次のセクションが並びます。

- **マシンの健全性**: 1台の Mac を1行で、FM(Foundation Models のテキスト・画像)と OCR / Vision の健全性を並べる。
  「現在の状態」の列は FM の Text・Image それぞれの alive・dead・unknown(● / ✕ / ? の記号)、
  ハードウェアビデオエンコーダー(AVE = Apple Video Encoder)の alive・dead・unknown(同じ記号。停止の理由はマウスを載せると出る)、直近の Vision の呼び出し・失敗件数、OCR モデルの
  コンパイル中、CPU / MEM の負荷。「集計期間」の列は run 履歴から、発生順に run 数・負荷による減速・
  OCR / Vision の注記・FM の枠待ち・FM 呼び出しの失敗・可視性検証の素通り・FM 停止の run 数を出す(マウスを載せると内訳や理由)。
  失敗や停止などがあるセルは警告色になる。モニターが観測できていない値、記録に欄が無い値は 0 にせず「–」。
  「集計期間」の列はプロジェクトの切り替えに関わらず、すべてのテストプロジェクトの run 履歴から集計する
- **デバイスの健全性**: 1台1行で、マシンの列でマシンごとにまとめる。デバイスモニターの今の状態(色と記号付き)・
  ストレージの使用量と、run 履歴の回数(run から除外された回数・振り直し・run 前の除外/修復・回復操作・
  アプリのクラッシュ)を並べる。欠けている値は「–」。「アクティブなデバイスを表示」がオン(既定)のときは、
  未起動のデバイスとモニターに居ないデバイスを隠す。ストレージの使用量は自動では測らず、
  **「ストレージ使用を更新」ボタン**を押したときだけ、動いている仮想デバイスを全台測る(実機は測らない)。
  モニターの起動前に測った値は、測り直すまで灰色で出す
- **最新の実行**: 前回(同じプロファイルの直前の実行)から新たに失敗したシナリオ・回復したシナリオを併記
- **直近の実行**: 行をクリックすると run 詳細が開く。失敗ステップの file:line はクリックでエディタの該当行を開く。
  「すべて / パフォーマンス計測のみ」で切り替えると、`--performance` を付けた run だけを並べる。
  左端のチェックで2件を選ぶと、その2件のシナリオごとの所要を比べる(開始の古い側を前回とし、両方で passed の
  シナリオだけを悪化の大きい順に並べる。profile や machine が違う2件には注記を出す)
- **注意喚起**(insights): 重大度ごとに見出しを分け、同じ種類の現象が4件以上あれば折りたたむ
- **不安定(flaky)なシナリオ**・シナリオ推移
- **実行時間が長いシナリオ**
- **シナリオ別サマリ**: シナリオIDでの絞り込み・「失敗を含むものだけ」・列見出しクリックでの並べ替えに対応

ツールバーの集計期間の切り替え(直近5分/10分/1時間/3時間/8時間/16時間/1日/2日/3日/7日/30日/90日。既定は直近16時間。選んだ期間は次に開いたときも引き継ぐ)で範囲を変えられます。期間内に run が無くても、マシンの健全性とデバイスの健全性は常に表示します。更新中も直前の表示は消えません
(裏で取得し直してから差し替えます)。

## 失敗テストの再実行とレポート

- **「失敗したテストを再実行」** は前回失敗したシナリオだけを再実行します。
- **「レポートを開く」** はシナリオの直近実行の Markdown レポート(要素一覧・スクリーンショット・
  可能なら自己修復の提案)を開きます。
- Test Explorer ツールバーの **「失敗したテストのみ表示」** フィルターでツリーを失敗したテストだけに
  絞り込めます。

## 自己修復

`fleetest.heal` を `true` にすると、**実行**(dry-run を除く)と**デバッグ**に `--set heal=true` が付与され、
セレクタの自己修復(指紋照合方式)が有効になります。修復の提案が出た実行は、終了時に直ったセレクタを
シナリオのソースへ自動で書き戻し、通知を出します。**「変更を表示」** で VSCode のソース管理ビューが開くので、
git の差分を確認してコミットしてください。書き戻せなかったものは実行ログに出ます
(詳細は [自己修復](../running/self_healing_ja.md))。

## 更新チェック

更新の確認と実行は「設定」タブの **「更新」** セクションに一本化されています。

- **「更新を確認」** は最新/新しいリリースあり/対象外(版固定)/確認できなかった、のいずれかを表示します
  (読み取りのみでリポジトリは変更しません)。新しいリリースがあるときは「新しいリリース X.Y.Z があります
  (現在 A.B.C)」と出し、**「変更内容」** ボタンでそのリリースノートを OUTPUT に表示します。
- **「更新する」** は更新があるときだけタブの隣に現れ、押すと最新リリースへの切り替え → 再ビルド → 拡張の
  再インストールを行い、完了後に再読み込みを促します。
- コマンド **「fleetest: 更新を確認」**(`fleetest.checkForUpdate`)は、1日1回の間隔・「通知しない」・
  `fleetest.updateCheck: off` を無視して必ず結果を返します。

`fleetest.updateCheck`(`auto`/`off`)は起動時(1日1回まで)の自動確認を制御し、`git ls-remote`
だけを行ってリポジトリを一切変更しません。

## 表示言語

`fleetest.language`(`auto`/`ja`/`en`)は拡張自体の UI 表示言語を制御します。`auto` は VSCode の
表示言語に追従します。「設定」タブの **「表示言語(Display Language)」** からも切り替えられます。

インストーラ(`Scripts/install.sh`)は、OS の言語が日本語なら `ja`、それ以外なら `en` を VSCode の
ユーザー設定へ書きます。既に `fleetest.language` を設定している場合は変更しません。

## ログ・録画のクリーンアップ

録画・レポート・ログは実行のたびに溜まるので、カテゴリごとに上限を決めて古いものから削除します。
設定は「設定」タブの **「ログ・録画」** セクションにあります。保存先は VSCode の設定ではなく
**この Mac の設定**(`fleetest api retention`)なので、ターミナルから直接実行したテストにも効きます。

- **「テスト完了後にバックグラウンドでクリーンアップする」**(既定 ON): テストが終わると裏で
  クリーンアップが走ります。テストの実行時間には含まれません。
- **上限**: 使用量が上限の 90% に達したカテゴリだけ、古いものから 90% まで削除します。
  空欄にするとその項目だけ既定値に戻ります(既定値は欄に薄く表示されます)。最小値より小さい値は
  最小値になります。

  | 項目 | 既定の上限 | 最小値 |
  |---|---|---|
  | デバイスの録画・スクショ | 2 GB | 1 GB |
  | 録画 | 50 GB | 2 GB |
  | レポート | 2000 MB | 100 MB |
  | ログ | 100 MB | 10 MB |
  | 実行ログ(`*.ndjson`) | 2 GB | 100 MB |
  | ブリッジ診断ログ | 5 GB | 1 GB |

- 各行の右に**現在の使用量**が出ます。集計に 20 秒ほどかかるため、その間は「現在 - GB」と
  表示されます。
- **「今すぐクリーンアップ」**: 同じ規則ですぐに削除します。削除する前に、消える合計を確認
  ダイアログで示します。
- 結果の記録(合否・所要時間の JSON)は削除の対象外です。
- **ブリッジ診断ログ**は、動いているブリッジの分を消せません。そこで、このカテゴリが上限を超えたときは、
  テスト・MCP・ライブ操作のどれにも使われていないブリッジを自動で起動し直し、古いログを消します
  (その間、そのデバイスの画面は数十秒止まります)。「テスト完了後にバックグラウンドでクリーンアップする」を
  OFF にすると、この起動し直しも止まります。
- レポートは、実行プロファイルで出力先(`reportDir`)を変えている場合はその場所も対象です。
  コマンドの `--report-dir` で1回だけ変えた出力先は対象外です。

### iOS Simulator の壁紙キャッシュ(CLI のみ)

iOS 27 の Simulator は、起動を繰り返すとキャッシュが溜まり、1台で数十 GB に達することがあります。
fleetest は Simulator を起動する直前に、そのデバイスのキャッシュを自動で消します(壁紙の設定など、
ほかのデータには触れません)。

停止中のデバイスの分をまとめて消したいときは、ターミナルから `fleetest clean --simulator-poster-cache` を
実行してください(`--dry-run` で消さずに量だけ確認できます)。**停止中**の全 Simulator ぶんを消し、起動中のデバイスは
名前だけ出して飛ばします。上のカテゴリや「設定」タブには含まれていません。

## 主要設定

| 設定 | 既定値 | 説明 |
|---|---|---|
| `fleetest.binaryPath` | `.build/debug/fleetest` | `fleetest` バイナリのパス。見つからなければ `PATH` から探す |
| `fleetest.project` | `""` | 対象のテストプロジェクト名。空なら自動判定(1つならそれ。複数なら `project1`) |
| `fleetest.profile` | `""` | 使用する実行プロファイル名。設定するとデバイス/アプリの決定がこちらに委ねられる |
| `fleetest.heal` | `false` | 実行/デバッグで `--set heal=true` を有効にし、自己修復を有効にする(修復したセレクタはシナリオへ書き戻される) |
| `fleetest.buildBeforeRun` | `true` | 実行前に Swift プロジェクトをビルドする |
| `fleetest.lptScheduling` | `true` | 過去の実行時間の記録から実行時間の長いシナリオを先に投入する(LPT) |
| `fleetest.monitorInterval` | `2` | デバイスモニターのポーリング間隔(秒) |
| `fleetest.language` | `"auto"` | 拡張の UI 表示言語 |
| `fleetest.updateCheck` | `"auto"` | 起動時(1日1回まで)の自動更新チェック |
