# type

[in English](type.md)

入力欄へ文字列を入力します。フォーカス中の要素へ入れる形と、要素を指定する形があります。

## 関数

| 関数 | 説明 |
|---|---|
| `type("文字列", replace: false, settle:)` | **フォーカス中**の要素へ入力します(先に `tap(入力欄)` でフォーカスしておきます)。引数は**テキストであってセレクタではありません** —— セレクタらしい1語(`#` で始まる・`\|\|` や `>>` を含む)を渡すと実行前に失敗します(黙って誤入力して後段の検証で落ちるのを防ぐため)。その文字列を本当に入力したいなら2引数形 `type("#field", "#email")` を使います。`replace: true` で撃つ前に(`clearInput` 相当で)クリアしてから入力します。 |
| `type(sel, "文字列", replace:settle:waitSeconds:scroll:maxSwipes:)` | 要素を解決してから入力します。日本語もそのまま入ります(IME 切替は不要)。`replace: true` で撃つ前にクリアしてから入力します。 |
| `select(sel).type("文字列", replace:waitSeconds:)` | 掴んだ要素へ入力します。掴んだときのセレクタで引き直すので、`type(sel, "文字列")` と同じ動きになります。掴めなかった要素からは失敗します。`findImage` / `findImages` で掴んだ要素へは入力できません(先に `.tap()` してから `type("文字列")` と書きます)。**入力するだけなら `type(sel, "文字列")` と書きます** —— `select` のぶん1ステップ多くなるだけです。 |

## 例

```swift
tap("#field")
type("abc")                        // 先にタップしてフォーカスを作ってから打つ

type("#email", "test@example.com") // セレクタ形。1コマンドで解決・フォーカス・入力
type("#note", "新しい内容", replace: true)

let field = select("#login_id")    // 掴んだ要素を後で使うときだけ
field.type("alice")                // type("#login_id", "alice") と同じ
```

## 注意点

- **ボタンなど入力欄でない要素を指すと、打つ前に失敗します。** `type` は打つ前に対象をタップするので、
  そのまま撃つと送信・購入などのボタンを押してしまいます。UI フレームワークが UIKit・SwiftUI・React Native・
  Android View と分かっていて、要素の型がボタン・スイッチ・リンクなどのときだけ断ります(Compose・Flutter は
  本物の入力欄が別の型で報告されることがあるので断りません)。入力欄を1つだけ包む要素を指したときは、
  警告を出して打ちます。
- **改行(`\n`)は OS 既定の挙動になります。** iOS では Return キー押下として届くため、
  複数行の欄なら改行が入り、単一行の欄なら確定アクション(検索・完了など)が発火します ——
  どちらになるかはフィールドが決めるものであり、`type` 側では選べません。Android も末尾の
  改行は Enter として送られます。確定アクションを撃つ意図なら
  [`pressEnter()`](./press_enter_hide_keyboard_ja.md) を使ってください。`type("腕時計\n")`
  は改行を入れたいのか送信したいのかがコードから読めません。
- **Android では、次の操作がソフトキーボードの表示を待ちます。** `type` はキーボードが出る前に返るため、
  次の操作は対象を解決する前に最大 1.5 秒、キーボードが出るのを待ちます(解決の後で画面が動くのを防ぐため)。
  出なければそのまま通常どおり進みます。
- **`tap(入力欄)` → `type("文字列")` の書き方をサポートしています。** Android の入力欄は
  容器(Material の `TextInputLayout`)と中身(`TextInputEditText`)に分かれ、`#id` は容器側に
  解決することが多くあります。容器をタップしても、必ずしも中の入力欄へフォーカスが移るとは
  限りません。`type` は直前の `tap` の後で焦点が立っていないと判断したときだけ、入力欄を
  名指しして入れ直します:

  ```
  ✅ type "abc"(typed into textField (the preceding tap did not put a field in focus))
  ```

  この復帰処理は**タップ直後の木1枚だけ**を見て、入れ先は「叩いた要素そのもの」か
  「その中のただ1つの入力欄」に限られます(入力欄が2つ以上あるときは何もしません)。
  発生したことは注記 `type-focus-recovered` に残ります。それでも入らないとき(欄が
  一意に決まらない等)はセレクタ形で書いてください —— `type(sel, "文字列")` は解決・
  フォーカス・読み返しまで1コマンドで引き受けます。

- **入った値は読み返して直します。** 末尾が欠けていれば追送、二重に入っていれば削除、
  **途中の1文字が落ちていれば(`hello123` → `hllo123`)消してから全文を打ち直します**
  (注記 `type-retyped`)。打ち直しは1回までです —— 打ち直しても同じ形で欠けるなら、それは
  打鍵の落ちではなくアプリ側の加工(英字を捨てる数字欄など)なので、検証を諦めてそのまま
  受け入れます(注記 `type-retype-abandoned`。値は `textIs` で別途確かめてください)。
- **値が1文字も動かないときは、先に画面を見ます。** 欄の値が入力を映さない欄(Material3 の
  SearchBar は iOS で値に説明文を出す)があるためです。打った文字が欄に描かれていれば(OCR)、
  打ち直さずに受け入れます(注記 `type-readback-unchanged`)。描かれていなければ入力が届かなかった
  ものとして追送します。**追送は1回まで**で、追送しても値が動かなければ失敗にします(撃ち直しを
  重ねると入力が重複しうるため)。
- **`settle: false`** を渡すと、このコマンドの操作後の「画面が落ち着くまでの待ち」を省きます(次のステップは動いている最中の画面を見ることがあります)。詳細は [tap](./tap_ja.md) 参照。
