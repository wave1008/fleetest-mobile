# 品質特性(非機能要件)

[in English](quality.md)

このページでは、fleetest の「機能」ではなく、**AI 親和性・安定性・安全性・プライバシー**といった
「使い心地と安心感」に関わる性質を紹介します。詳しい説明は各項目のリンク先にあります。

## AI 親和性

fleetest は、AIアシスタントへ指示して使うことを前提に作られています。

- **自然な言葉で AIアシスタントへ指示するだけで使えます。**
  「ログイン画面のテストを作って」「失敗の原因を調べて」のように AIアシスタントへ指示すれば、テストを作り、実行し、
  結果を報告します。テストコードを自分で読み書きする必要はありません
  ([AIアシスタントへの指示の仕方](../tutorial/asking_ai_ja.md))。
- **AI がアプリを実際に操作して、画面を読めます。**
  MCP サーバを通じて、AIアシスタントがデバイス上のアプリをタップしたり入力したりし、画面の内容を AI が
  読みやすい短いテキストで受け取ります。推測ではなく、実際の画面からテストを組み立てます
  ([MCP サーバ](../reference/tools/mcp_server_ja.md))。
- **AI が自分で誤りに気づけます。**
  操作した手順からテストの下書きを作り、コンパイルと dry-run で、デバイスを動かす前に書き間違いを見つけます
  ([エージェント向けの手引き](../reference/tools/agent_guide_ja.md))。
- **失敗の原因を AI が調べやすい形で返します。**
  テストが失敗すると、失敗した手順に加えて、その瞬間の画面の要素一覧とスクリーンショットを返します。
  過去の結果も AI から問い合わせられるので、不安定なテストや遅くなったテストを AI に探させられます
  ([結果を読み、失敗を調べる](../tutorial/investigating_failures_ja.md))。
- **作業の手順書が付いています。**
  導入・プロファイル作成・テスト作成の手順書(Claude Code のスキル)があり、AIアシスタントはそれに沿って
  確認を挟みながら進めます([Claude Code のスキル](../reference/tools/claude_code_skills_ja.md))。
- **特定の AI に縛られません。**
  Claude Code のほか、MCP に対応した AIアシスタント(Codex・Cline・Cursor など)でも使えます
  ([Claude Code 以外の AIアシスタント](../reference/tools/other_agents_ja.md))。

## 同期の自動化・パフォーマンスの最適化

- **画面との同期は自動です。**
  ボタンを押したあと「とりあえず3秒待つ」といった待ち方はせず、画面の動きが止まったのを確かめた時点で
  次の操作に進みます。テストに待ち時間を書いて調整する必要はなく、無駄に待つこともありません。
- **iOS Simulator では、アプリ内で高速に動作する in-app エンジンを併用して速度をブーストします。**
  ハイブリッドエンジンは XCUITest エンジンと in-app エンジンの切り替えを自動で行い、パフォーマンスを最適化します
  ([fleetest とは](about_ja.md))。

## フリートによるテストの並列実行

- **Simulator・Emulator・物理端末をグルーピングした単位(=フリート)でテストを並列実行できます。**
  プロセッサのマルチコアを最大限に活用します([並列実行](../reference/running/parallel_execution_ja.md))。
- **Mac を追加すればネットワーク越しのリモートランナーとして利用できます。**
  また、リモートランナー上のデバイスもフリートに追加することができます
  ([リモート実行](../fleet/remote_runners_ja.md))。

## 耐障害性

- **不調なデバイスを自動で復旧します。**
  デバイスとの通信が途切れたときは自動で復旧を試みます。
- **テストの途中でデバイスが固まるなど、デバイスの不具合で落ちたテストは、別のデバイスでやり直します。**
  用意するデバイスに予備を1台含めて待機します。

## データの自動クリーンアップ

- **デバイスや Mac に溜まった不要なデータを定期的に片付けます。**
  デバイスのキャッシュやログの削除と、容量が膨らんだ Android Emulator のデータの初期化を自動化します
  ([長く使うためのメンテナンス](../in_action/maintenance_ja.md))。

## 再現性・経済性

- **テストコードの作成は AI で行うのが前提ですが、テストの実行は AI に委ねません。**
  テストコードによって毎回同じ手順で動くので、結果がぶれず、実行のたびに AI の利用料がかかることもありません。

## セキュリティ

テストコードに有害なコードが混入した場合に、リスクを抑える仕組みがあります。

- **テストは常にサンドボックスの中で動きます。**
  テストが読み書きできるファイル、通信できる相手、できる操作を制限しています。たとえば SSH の鍵やキーチェーンのような大事なファイルは読めません
  ([サンドボックスの考え方](../security/sandbox_ja.md))。
- **外部と通信できるのは、許可した相手だけです。**
  テストからインターネットへ通信できるのは、設定 `allowedDomains` に書いた宛先だけです
  ([アクセスできるフォルダと通信先](../security/access_ja.md))。

## プライバシー

- **データは自分が Mac とデバイスで構成したフリートの外に出ません。**
  クラウドサービスにはアクセスしません。
- **一部の機能で Apple のローカル LLM である FM(Foundation Models)を使用しますが、Apple のクラウド(Private Cloud Compute)は利用しません。**
- **テストの作成は Claude や GPT などのフロンティアモデルの利用を推奨しますが、セキュリティ要件が厳しい場合はローカル LLM を使用することもできます。**
- **本物のパスワードはテストに書かないでください。**
  アカウント情報を記録の中で伏せ字にする設定(既定はオフ)はありますが、スクリーンショットや録画に写った文字までは
  隠せません。テスト用のアカウントを使ってください。

## カスタマイズ性

テストコードは普通の Swift なので、組み込みのコマンドで足りないところは自分で足せます。fleetest 本体を
改造する必要はありません([自分で機能を足す](../reference/writing/extending_ja.md))。

- **よく使う手順を、自分のコマンドにできます。**
  ログインや「カートを空にする」のような繰り返しの手順を Swift の関数にまとめ、どのテストからも呼び出せます。
  説明を付けておくと、テストを書く AIアシスタントもその関数を見つけて使うようになり、同じ手順を
  書き直さずに済みます([独自コマンド](../reference/testclass/custom_commands_ja.md))。
- **組み込みのコマンドに無い処理も書けます。**
  任意の Swift の処理を、名前を付けた1つの手順としてテストに入れられます。
- **テストデータや外部のサーバとつなげます。**
  アカウントやテストデータをファイルから読んだり、テスト用の API を呼んで前提のデータを作ったりできます。
- **ライブラリや共通部品を使えます。**
  Swift のパッケージを追加して、ライブラリやチームの共通部品をテストで使えます。
- **テストの前後に、準備と後片付けの処理を走らせられます。**
  データベースやスタブサーバの用意などを、テストの実行の前後に自動で行えます。

自分で足した処理も、セキュリティの節で説明したサンドボックスの中で動きます。

## 規模の拡大

- **複数のデバイスで分担して回せます。**
  Simulator・Emulator・実機を混ぜて、複数のテストを同時に回せます。1台の Mac で増やせる台数には
  上限があるので、それを超えるときは Mac を増やします
  ([並列実行](../reference/running/parallel_execution_ja.md))。
- **Mac を増やすこともできます。**
  別の Mac にテストを送って、複数の Mac で分担して回せます([リモート実行](../fleet/remote_runners_ja.md))。

## 運用のしやすさ

- **CI に組み込めます。**
  合否を終了コードと JUnit 形式のファイルで返すので、CI のツールでそのまま扱えます
  ([CI で回す](../in_action/ci_ja.md))。
- **結果を後から調べられます。**
  実行結果は記録され、どのテストがどこでよく落ちているかを後から集計できます
  ([結果の分析](../reference/running/results_analysis_ja.md))。
- **実行中の様子を見られます。**
  VSCode 拡張で、各デバイスの画面と実行ログをリアルタイムに見られます
  ([VSCode 拡張](../reference/tools/vscode_extension_ja.md))。
- **ディスクの掃除は自動です。**
  録画やログは、容量の上限に近づくと古いものから自動で消えます
  ([長く使うためのメンテナンス](../in_action/maintenance_ja.md))。

## 導入のしやすさ

- **アプリを作り変える必要はありません。**
  テスト用の部品を組み込んだり、テスト専用のビルドを作ったりする必要はありません。普段の開発で使っている
  アプリをそのまま使えます。
- **無料です。** テストを実行するたびにお金がかかることもありません(AIアシスタントの利用料は別です)。
- **必要なもの**: Apple silicon の Mac。iOS と Android の両方、主な開発方法(SwiftUI / UIKit・View/XML・
  Compose Multiplatform・Flutter・React Native)で作られたアプリで動作を確認しています([環境](environments_ja.md))。
