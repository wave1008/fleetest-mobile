# Fleetest とは

Fleetest は iOS / Android アプリの E2E テストツールです。macOS 上で動き、Claude Code などの
コーディングエージェントと組み合わせて使うことを前提に設計されています。

## 名前に込めた3つの特徴

**fleetest** は `fleet` + `test`。同時に、*fleet*(すばやい)の最上級形でもあります。

- **fleet** —— デバイスの**フリート**で並列にテストします。シミュレータ・エミュレータ・実機、
  SSH 越しの別の Mac まで束ねられます。シナリオは自動で分配されるので、台数を増やすほど
  実行時間が縮みます。
- **fleetest** —— 再生に LLM を挟まないので**最速**です。実行時間を決めるのはモデルではなく
  デバイスです。
- **free** —— テスト実行は**無料**です。クラウドのデバイスファームも、実行ごとの API 課金も
  ありません。

## AI がテストを作り、コードが決定的に再生する

テストの「作成」と「実行」で、役割をはっきり分けています。

**作るのは AI(または人)です。** 作り方は3通りあり、どれも同じ Swift シナリオになります。

- VSCode 拡張のライブ操作パネルで、アプリの操作を録画する
- エージェントに書かせる —— 実画面を探索しながらセレクタを採取します
- 手書きする —— イレギュラー処理やテストデータ投入も Swift でそのまま書けます

**再生するのはコードです。** シナリオは LLM なしで決定的に実行されます。速く、安定していて、
CI 向きです。

**AI が介入するのは失敗したときだけです。** 壊れたセレクタの自己修復、スクリーンショットの
視覚検証、失敗原因のトリアージ。これらはすべて Apple のオンデバイスモデル
(Foundation Models)で動くので、アプリの画面情報が Mac の外に出ることはありません。

## 4つの入口

用途に応じて入口は4つありますが、中身は同じコアです。どの入口で作ったテストも同じ `.swift`
ファイルになり、どの入口からでも実行できます。

| 入口 | 向いている用途 |
|---|---|
| **VSCode 拡張** | 人間の対話操作。デバイスモニター・ライブ操作(録画 → 生成)・実行・結果ダッシュボード |
| **MCP サーバ** | エージェント連携。AI によるテスト作成・デバッグ・探索的テスト |
| **CLI** `fleetest` | CI・回帰テストの定期実行 |
| **Swift DSL** | テスト資産そのもの。`TestProjects/<name>/scenarios/*.swift` |

## しくみ

デバイスの操作は自作の常駐ブリッジで行います。iOS はシミュレータ内の XCUITest プロセスと
HTTP で、Android は adb 越しのブリッジと通信します。Appium などの外部ドライバには
依存しません。

プラットフォームの違いはドライバ層で吸収され、再生エンジンと Foundation Models の呼び出しは
iOS / Android で完全に共通です。
