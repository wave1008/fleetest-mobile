# VSCode 拡張

`vscode-fleetest` 拡張は、シナリオを VSCode の Test Explorer に表示し、その周りにデバイス操作・
ライブ確認・結果レビューの機能を追加します。ターミナルと同じ `fleetest` CLI を spawn して動くため、
挙動は CLI・MCP と同じになります。

## Test Explorer

シナリオは `TestProjects/<project>/scenarios/**/*.swift` から構成される
folder → class → `@Test` メソッドの3階層ツリーとして Testing ビューに表示されます。対象の
`<project>` は `fleetest.project` 設定で選びます。空のときは自動判定で、拡張は起動時に
`TestProjects/default/` が無ければ `fleetest project create default` で作成し、これを初期選択にします
([テストプロジェクトの作成](../project/creating_project_ja.md))。各テスト項目には
3つの実行プロファイルがあります。

- **実行** — デバイス上でシナリオを実行します。
- **実行 (dry-run)** — デバイス不要でシナリオを検証します(セレクタの構文誤り・到達しない
  scene・アサーションの無い expectation・保存済みスナップショットに実在しない `#id` など)。
- **デバッグ** — DAP(Debug Adapter Protocol)アダプタ経由で実行します。`action { }` ブロック内の
  コマンド行にブレークポイントを設定し、デバッグツールバーでステップオーバー・続行・停止ができます。

`fleetest.profile` を設定すると、実行・実行(dry-run)・デバッグはいずれも生の
`fleetest.platform`/`fleetest.port`/`fleetest.serial` ではなく `fleetest api run --profile <name>`
経由になります。デバイスの供給とアプリの自動インストールは実行プロファイル側が行います。
dry-run 以外の実行では対象デバイスがあらかじめ起動済みである必要があります。dry-run はデバイス
不要です。

## ステップ一覧

読み取り専用の **fleetest ステップ** TreeView(Testing ビューコンテナ内)がカーソル位置に追従します。
`@Test` メソッドの本体内にカーソルを置くと、そのシナリオの `scene` グループとステップの一覧が
表示されます。ステップをクリックすると対応するソース行にジャンプします。シナリオの右クリック
メニュー(「fleetest: ステップ一覧を表示」)からも開けます。

## デバイスモニター

コマンド **「fleetest: デバイスモニターを表示」** を実行するか、VSCode 左下のステータスバーの
**fleetest mobile** をクリックすると、デバイスタイルの一覧を表示する
Webview パネルが開きます(1ワークスペースにつき1枚)。各タイルにはデバイス名・プラットフォーム
バッジ(iOS/Android)・状態バッジ・現在の画面が表示され、画面は既定でヘッドレス映像ストリーミング
(`fleetest-simstream`/`fleetest-androidstream`)によりほぼリアルタイムに更新されます
(ストリーミングが使えない場合は定期的なスクリーンショット取得にフォールバックします)。

- 状態バッジ: **接続済み**(緑) — ブリッジ接続済みで操作可能 / **起動中**(黄) — デバイスは
  起動しているがブリッジ未接続 / **未起動**(灰) — デバイス停止中。
- タイルを右クリックするとそのデバイス1台だけを起動/停止できます
  (`fleetest api start-device`/`stop-device`)。デバイス操作は共有の1本のキューで1件ずつ実行される
  ため、順番待ちのタイルには「待機中...」バッジが表示されます。
- ツールバーのボタンで表示中の全デバイスの起動/停止、モニタープロセスの再起動ができます。
- ツールバーの下の **run ボード**には、この Mac と登録したランナー機で**いま走っている実行**が
  「何本中何本」「残り何分」つきで並びます(自分が起こした実行に限らず、CLI や別の人の実行も
  出ます)。行をクリックするとその実行のデバイスがラインビューで選択されます。
- 「デバイスモニター」タブは上から **ラインビュー**(デバイスタイルの並び)・**グリッドビュー**
  (選択した台の画面の拡大表示)・**実行ログビュー**(選択した台の実行ログ)の3つに分かれます。
  境界線のドラッグで高さを、見出し行のクリックで開閉を変えられます(どの高さにしても見出し行は残ります)。
- グリッドビューと実行ログビューに出るのは**ラインビューで選択した台だけ**です。タイルはどこを
  押しても選択の入り切りが変わり、タイルの外側を押すと選択が全部外れます。1台も選んでいないときは
  どちらのビューにも「デバイスを選択して下さい」と出ます(実行中の供給の進行は実行ログビューに出ます)。
  ちょうど1台だけ選んだときは、グリッドビューの中に拡大表示とその台の実行ログが横に並び、
  下の実行ログビューは同じログが二重にならないよう自動で畳まれます。
- run ボードの見出し行にある **iOS / Android / すべて**(既定は「すべて」)で、4つのセクション
  (実行中・デバイス一覧・選択したデバイス・実行ログ)に出すデバイスをプラットフォームで絞れます。
  デバイス自体は止まりません(表示だけ)。
- ラインビューの見出し行にある **「ライブ更新」** を OFF にすると、全デバイスの画面の配信と
  取り込みを止めて Mac の負荷を下げます。タイルは最後の画面のまま暗く表示されます
  (状態の表示は更新が続きます)。
- **「テストセッション」タブ**では録画のある実行(実行プロファイルの `record: true`)を一覧から開き、シナリオごとの
  動画・ステップのツリー・エラー一覧を見られます。**「デバイスモニター」タブを表示したまま実行が終わると**、
  録画の準備ができた時点で自動的に「テストセッション」タブへ切り替わり、その実行の録画が開きます(他のタブを
  表示しているときは切り替えません。録画の無い実行・キャンセルした実行も切り替えません)。
  テストが全部終わってから切り替わるまでの間は、「テストを実行」ボタンの右に「録画を編集中...」と表示されます。
  再生ビューのヘッダーにある **「テスト結果をエクスポート」** ボタンで、開いているセッションの結果を
  Excel(.xlsx)ファイルへ書き出せます。保存先はダイアログで選べます。
- **「プロファイル」タブ**ではテストプロジェクト自体の一覧・作成・コピー・名前変更・削除と、
  実行/アプリプロファイルの一覧・作成・コピー・名前変更・削除・編集ができます。実行プロファイルの
  節には全実行プロファイルのデバイスの和集合がチェックボックス付きで並び(チェック済み=その
  プロファイルが走らせる)、「デバイスを追加」ボタンもここにあります。
- **「設定」タブ**には表示・更新・ログと録画のクリーンアップ・リモート実行のマシン登録に関する
  設定があり、下記の更新チェック・更新の実行もここから行います。一番上の **「ツール」** には
  「プロセス」のボタンがあり、押すとそのタブが現れます。
- **「ライブ操作」タブ**(下記)と **「プロセス」タブ**(fleetest の常駐プロセスの一覧と停止)は起動時には
  出ません。開くとタブが現れ、タブの × で閉じられます。
- 画面のどこで右クリックしても、既定の「切り取り/コピー/貼り付け」のメニューは出ません(文字を打つ
  入力欄を除く)。

## ライブ操作

デバイスの画面を直接操作するタブで、デバイスモニターの「デバイスモニター」タブの右隣に現れます。
コマンド **「fleetest: ライブ操作を表示」**・タイルの右クリック
**「ライブ操作」**(そのデバイスを選んだ状態で開く)から開けます。テストの実行開始時にも自動で開きます
(設定 `fleetest.liveControlOnRun`)。

対象デバイスのブリッジがまだ起動していない場合は自動で起動し、エラーではなく短い
「デバイスに接続しています…」という表示になります —— 通常は既存のビルドを再利用するため
数十秒程度で、そのデバイス向けの最初のビルドだけ長くかかります。

| 操作 | 動作 |
|---|---|
| クリック | タップ |
| 動かさず約500msホールド | 長押し |
| ドラッグ | スワイプ(方向は始点終点の差分から自動判定) |
| Shift(⇧)+ドラッグ | 指の軌跡どおりになぞる(ツールバーの「軌跡」は Shift を押している間だけ点灯する。離さない1本のタッチ。押したまま止まってから動かすと長押しからのドラッグになる。なぞった時間どおりに再生する。60 秒を超えた時点で中止してエラーを出し、離しても送らない) |
| Option(⌥)+クリック | ダブルタップ |
| ツールバーの拡大・縮小 | ピンチ(画面全体) |

iOS の Compose アプリでは、実機と `xcuitest` だけの構成でダブルタップ(Option(⌥)+クリック)が効きません。
拡大したいときはツールバーの拡大(ピンチ)を使ってください([ジェスチャ](../commands/gestures_ja.md))。

画像の横に並ぶ要素一覧をクリックすると、座標指定の代わりにその要素をタップできます。テキスト
入力欄は、デバイス側でフォーカスしている要素へ入力を送ります(先に入力欄をタップしてください)。

対象アプリが前面から外れても操作は続けられます(iOS)。ホーム画面・アプリスイッチャー・別のアプリ・
システムダイアログが前面になると、画面に映っているものをそのまま触れるように切り替わり、要素一覧も
そちらに変わります。対象アプリが前面に戻れば自動で元に戻ります(戻らないときはツールバーから
そのアプリを起動してください)。

**レコーディング**: 「レコーディング開始」で操作の記録を始め、一連の操作を行ってから
「レコーディング終了」を押すと、記録した操作が `fleetest api gen-scenario` により
`TestProjects/<project>/scenarios/Generated/` 配下の Swift シナリオに変換されます。生成直後に
ビルド検証が行われ、コンパイルに失敗した場合はツリーに追加されず `scenarios/_disabled/` へ
隔離されます。

## 結果ダッシュボード

コマンド **「fleetest: 結果ダッシュボードを開く」** を実行すると、デバイスモニターの **「ダッシュボード」タブ**に
プロジェクトの `fleetest api results` の集計が表示されます。直近の実行一覧・シナリオ別の成功率と
実行時間・不安定(flaky)シナリオ・デバイス/ワーカー別集計・日次の推移・実行時間が長いシナリオ・
その他の注意喚起(insights)が表示されます。

## 失敗テストの再実行とレポート

- **「失敗したテストを再実行」** は前回失敗したシナリオだけを再実行します。
- **「レポートを開く」** はシナリオの直近実行の Markdown レポート(要素一覧・スクリーンショット・
  可能なら自己修復の提案)を開きます。
- Test Explorer ツールバーの **「失敗したテストのみ表示」** フィルターでツリーを失敗したテストだけに
  絞り込めます。

## 自己修復の確認

`fleetest.heal` を `true` にすると、**実行**(dry-run を除く)と**デバッグ**に `--set heal=true` が付与され、
セレクタの自己修復(指紋照合方式)が有効になります。実行結果に修復候補が含まれると、終了後に確認パネルが
自動的に開きます。各候補には file:line・変更前/変更後セレクタ(変更後は編集可)・任意の説明・
ライブに追従する diff プレビューが表示されます。承認するとシナリオソースへ直接反映されます。
対象行が記録済みの変更前セレクタと一致しなくなっている候補は「適用できません」と表示されます。

## 更新チェック

更新の確認と実行は「設定」タブの **「更新」** セクションに一本化されています。

- **「更新を確認」** は最新/更新あり/対象外(版固定)/確認できなかった、のいずれかを表示します
  (読み取りのみでリポジトリは変更しません)。
- **「更新する」** は更新があるときだけタブの隣に現れ、押すと pull → 再ビルド → 拡張の
  再インストールを行い、完了後に再読み込みを促します。
- コマンド **「fleetest: 更新を確認」**(`fleetest.checkForUpdate`)は、1日1回の間隔・「通知しない」・
  `fleetest.updateCheck: off` を無視して必ず結果を返します。

`fleetest.updateCheck`(`auto`/`off`)は起動時(1日1回まで)の自動確認を制御し、`git ls-remote`
だけを行ってリポジトリを一切変更しません。

## 表示言語

`fleetest.language`(`auto`/`ja`/`en`)は拡張自体の UI 表示言語を制御します。`auto` は VSCode の
表示言語に追従します。「設定」タブの **「表示言語(Display Language)」** からも切り替えられます。

## ログ・録画のクリーンアップ

録画・レポート・ログは実行のたびに溜まるので、カテゴリごとに上限を決めて古いものから削除します。
設定は「設定」タブの **「ログ・録画」** セクションにあります。保存先は VSCode の設定ではなく
**この Mac の設定**(`fleetest api retention`)なので、ターミナルから直接実行したテストにも効きます。

- **「テスト完了後にバックグラウンドでクリーンアップする」**(既定 ON): テストが終わると裏で
  クリーンアップが走ります。テストの実行時間には含まれません。
- **上限**: 使用量が上限の 90% に達したカテゴリだけ、古いものから 90% まで削除します。
  空欄にするとその項目だけ既定値に戻ります(既定値は欄に薄く表示されます)。最小値より小さい値は
  最小値になります。

  | 項目 | 既定の上限 | 最小値 |
  |---|---|---|
  | デバイスの録画・スクショ | 2 GB | 1 GB |
  | 録画 | 50 GB | 2 GB |
  | レポート | 2000 MB | 100 MB |
  | ログ | 100 MB | 10 MB |
  | ブリッジ診断ログ | 5 GB | 1 GB |

- 各行の右に**現在の使用量**が出ます。集計に 20 秒ほどかかるため、その間は「現在 - GB」と
  表示されます。
- **「今すぐクリーンアップ」**: 同じ規則ですぐに削除します。削除する前に、消える合計を確認
  ダイアログで示します。
- 結果の記録(合否・所要時間の JSON)は削除の対象外です。

## 主要設定

| 設定 | 既定値 | 説明 |
|---|---|---|
| `fleetest.binaryPath` | `.build/debug/fleetest` | `fleetest` バイナリのパス。見つからなければ `PATH` から探す |
| `fleetest.project` | `""` | 対象のテストプロジェクト名。空なら自動判定(1つならそれ。複数なら `default`) |
| `fleetest.profile` | `""` | 使用する実行プロファイル名。設定するとデバイス/アプリの決定がこちらに委ねられる |
| `fleetest.heal` | `false` | 実行/デバッグで `--set heal=true` を有効にし、自己修復の確認パネルを開く |
| `fleetest.buildBeforeRun` | `true` | 実行前に Swift プロジェクトをビルドする |
| `fleetest.lptScheduling` | `true` | 過去の実測から実行時間の長いシナリオを先に投入する(LPT) |
| `fleetest.monitorInterval` | `2` | デバイスモニターのポーリング間隔(秒) |
| `fleetest.liveControlOnRun` | `true` | テスト実行(dry-run 以外)開始時にライブ操作を自動表示する |
| `fleetest.language` | `"auto"` | 拡張の UI 表示言語 |
| `fleetest.updateCheck` | `"auto"` | 起動時(1日1回まで)の自動更新チェック |
