# 移行メモ(既存シナリオの書き換え)

`ftester` を更新したとき、**手元のシナリオ(.swift)を直す必要がある変更**だけをここに置く。
新機能の追加は対象外(README / docs/design.md を見る)。読者は受け手と保守者の両方。

各項目は「症状 → 置換」の形。いずれも**実行前か実行時に必ず気付ける**(黙って緑にはならない)。

## 2026-07-26: セレクタ記法の刷新

この3件は同じ更新に入っている。`ftester run` すれば構文エラーか解決失敗として現れる。

### 1. 近接セレクタ `:near(...)` の廃止 → 方向セレクタ

**症状**: `未知のセレクタ構文 ":near(" です`(実行前に落ちる)

```swift
// 旧
tap(".Button=項目:near(#btn_allow)")
// 新(アンカーから見てどちら側かを明示する)
tap(".button=項目:below(#btn_allow)")
```

`:right` / `:left` / `:above` / `:below` の4つ。アンカーと**帯が重なり**、その方向にある候補のうち
最も近いものを選ぶ。**該当が無ければ解決失敗**(旧 `:near` は必ず1つ返していた)。
どの方向に置き換えるかは、実画面(`ft_snapshot`)でアンカーと対象の位置関係を見て決める。

### 2. 型名は先頭小文字

**症状**: `型名は先頭小文字で書きます: ".Button" → ".button"`(実行前に落ちる)

```swift
tap(".Button[2]")        // 旧
tap(".button[2]")        // 新
exist("#list >> .Cell")  // 旧
exist("#list >> .clickable")  // 新(下記3も参照)
```

スナップショット(`ft_snapshot` / 拡張のライブ操作パネル)が返す型名も同じ綴りになったので、
**見た型名をそのまま書けばよい**。

### 3. 型 `cell` → `clickable`

**症状**: `ロケータを解決できません: Cell[2]`(実行時に落ちる。構文としては正しいため)

```swift
exist("#list_rows >> .cell[2]")       // 旧
exist("#list_rows >> .clickable[2]")  // 新
```

「タップできるが役割が確定しない容器」(リスト行・カード・iOS のセル)という実態に名前を合わせた。

### ついでに消せるもの(必須ではない)

型の役割正規化により、**ボタン・スイッチ・テキストの型が iOS/Android で一致**した。
型のためだけに書いていた `ios {}` / `android {}` 分岐は削除できる:

```swift
// 旧
ios { tap(".Button=送信") }
android { tap(".Cell=送信") }
// 新
tap(".button=送信")
```

OS を跨いで保証される型は `button` / `staticText` / `textField` / `secureTextField` / `switch` の5つ。
`checkBox` / `slider` / リスト行は iOS 側が役割を出さないため揃わない → `#id` で指す。
チェック状態は型に依存せず `isChecked` / `isNotChecked` で検証できる。
