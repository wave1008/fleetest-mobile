# irregularHandler

出るか不定のアプリ内メッセージ(お知らせ・キャンペーン)を宣言し、出た時点で自動的に閉じます。

## 関数

| 関数 | 説明 |
|---|---|
| `irregularHandler(検出sel, dismiss: 閉じるsel?, maxDismissals: 10)` | 割り込みを宣言します。以降のどのステップでも(操作でも検証でも)`検出sel` が解決できた時点で自動的に閉じます —— `dismiss` があればそれをタップ、無ければ `検出sel` 自体をタップします。通常は `setUp()` で1回宣言します。 |

## 例

```swift
func setUp() {
    irregularHandler("#promo_modal", dismiss: "#btn_promo_close")
}
```

## 注意点

- **操作の待機中・検証の待機中どちらでも発火します。** 検証コマンドは各ポーリング周回で
  現在の木を評価するため、`exist` / `textIs` の待機中に開いたモーダルも、タップの最中に
  開いたモーダルと同じように閉じられます。
- **既定では1ステップにつき最大10回まで**閉じます(`maxDismissals:` で変更可能)。ステップの
  途中で同じモーダルが再び開いても閉じ切れます。2回閉じても同じものが画面に残っていれば
  諦め、「完全には閉じられなかった」と記録します。
- **条件判定も、割り込みを閉じてから答えます。** `ifCanSelect` / `repeatWhileCanSelect` は
  対象が宣言済みの割り込みに覆われているとき、先にそれを閉じてから判定します —— 閉じずに
  判定すると、覆われた対象が黙って「無い」と読まれ、失敗ではなく誤った分岐として現れて
  しまうためです。判定が不成立でも、閉じたことは記録に残ります。
- **OS のシステムダイアログ(権限の許可等)には効きません** —— あれらは別プロセスが描画して
  おり、`irregularHandler` の見える範囲の外です。[iosAlertHandler](./ios_alert_handler_ja.md)
  を参照してください。
- **別ウィンドウのモーダル(iOS)**: 一部のアプリ内メッセージ SDK は、アプリ本体とは別の
  `UIWindow` にカードを載せます。ツールはこれも扱います。
  - **モーダル自体は木に載ります**(`exist` で検証でき、`irregularHandler` で閉じられます)。
  - **モーダルが全面を覆っている場合、覆われた背面は木から消えます** —— 下にある要素の
    `exist` は失敗し、タップも「見つからない」で失敗するので、覆われた画面が誤って成功と
    読まれることはありません。
  - 画面の一部だけを覆う形(上部バナー等)では残りの要素はそのまま残ります —— 判定は
    「その位置で手前の窓が実際にタッチを受けるか」であって、見た目で隠れているかではあり
    ません。
  - タップ・スクロール・スクリーンショットはすべて、その時点で最前面にある窓へ届きます
    (必ずしもアプリのメインウィンドウとは限りません)。

### 割り込みが操作を吸ったとき

送った操作が効果を出すまでの**間**に宣言済みの割り込みが出た場合、ツールはその操作が
既に着弾したかどうかを判断できません。**撃ち直しは行いません** —— 届いていた場合に二重実行
(送信・購入の重複)になり得るためです。割り込みを閉じたステップがそのまま失敗すると、
次のような注記が残ります。

```
the interruption appeared during this step — an interaction sent just before it
may have been swallowed by it (nothing was re-sent: repeating it could double-fire)
```

ここからの復帰はシナリオ側の仕事です —— 意図した状態になっているか確かめ(`ifCanSelect` 等)、
なっていなければ叩き直しますが、**もう一度実行しても安全な操作にだけ**行ってください。
画面遷移のタップは安全ですが、確定・送信・支払いの操作は安全かどうかを書き手だけが判断
できるため、そのままでは行いません。
