# 要素の選択と検証

要素を掴んで状態を検証する基本を説明します。`tap` / `exist` / `select` の違いと、
値・テキストの検証コマンドが「直前に掴んだ要素」を対象にする仕組みです。

## `tap` / `exist` / `select` の違い

- **`tap(sel)`** はセレクタを解決してタップします。一致する要素が無ければコマンドが失敗し、
  シナリオが中断します。
- **`exist(sel)`** は検証コマンドです。一致する要素が無ければ失敗(シナリオ中断)し、結果は
  レポートに検証ステップとして残ります。戻り値へさらに検証をチェーンできます。
- **`select(sel)`** は要素を**掴むだけ**です —— デバイス操作は無く、指定していない可視性の
  確認も既定では行いません。一致する要素が無くても**失敗させません**。空要素を返すだけで、
  `select` 自体は**レポートに検証として残りません**(「アサーション1本以上」の判定にも数えません)。
  値を読みたいだけのとき、あるいはレポートに余分な検証点を増やさずに検証をチェーンしたいときに
  使います。

## 検証は「セレクタ」ではなく「直前に掴んだ要素」を対象にする

テキスト・値の検証コマンド(`textIs` / `valueIs` とその一族。
[テキストの検証](../commands/text_assertion_ja.md)参照)はセレクタを引数に取りません。
先に要素を掴み、そのあとで検証します。次の3つはまったく同じ意味です。

```swift
select("#login_btn").textIs("ログイン")              // 戻り値へチェーン
select("#login_btn"); lastElement.textIs("ログイン")  // 掴んだ要素を明示
select("#login_btn"); textIs("ログイン")              // 暗黙(直前に掴んだ要素が対象)
```

`textIs("#login_btn", "ログイン")` のように検証コマンドへ直接セレクタを渡す形は
**コンパイルが通りません**。先に掴んでから検証してください。

## `exist` の戻り値へのチェーン

```swift
exist("#total")
    .textStartsWith("合計")
    .textEndsWith("円")
```

既に掴んだ1つの要素に対して働くコマンドはこのようにチェーンでき、同じ集合は引数無しの
暗黙形でも書けます(上の例)。

## 暗黙の待ち

要素の解決は、最初の1回で失敗させるのではなく、タイムアウトまでリトライします。

- **操作系(`tap` / `type` など)**: 既定の `timeout:` は約 0.7 秒。
- **`select` と検証系(`exist` / `textIs` など)**: 既定の `timeout:` は 5 秒
  (実行プロファイルの `defaultTimeout`)。

どちらも `timeout:` を明示すれば(小数可。`timeout: 1.2` 等)、その呼び出しだけ既定値を
上書きできます。

## 可視性・偽陽性検証

`requireVisible: false` を渡すと、`exist`(通常は覆われ・見切れを検出して検証結果を失敗に
反転させる)と `select`(通常は空要素を返す)を裏で支えている可視性確認を省きます。
この追加の可視性照合は、実行プロファイルで `falsePositiveCheck: true` にした run でだけ
実際に走ります —— それ以外の run では、このフラグ自体に省くべき処理がありません。
