# リモートランナー セットアップ runbook

> **ユーザーへの質問(AskUserQuestion)・報告・チェックポイントはユーザーの言語で行う**。
> この手順書は日本語だが、読者はエージェントであり利用者の言語とは独立している。

手元の Mac から**別の Mac(ランナー機)へジョブ単位でディスパッチする**ための導入。
実行は `ftester run --host <ホスト>` になり、シナリオとプロファイルは実行のたびに自動転送される。

**利用者向けの全体像・前提の一覧・トラブルシュート表は docs/remote-runner-setup.md**
(この手順書と重複させない。詳細を聞かれたらそちらを読んで答える)。

## 前提(満たしていなければ先に済ませる)

- **手元**が既にセットアップ済み(`/ftester-setup` 済み。`ftester` がビルドされている)
- **ランナー機**が Apple silicon の Mac で、手元と**同じ macOS + 同じ Xcode**
  (指紋が1文字でも違うと全ディスパッチが止まる)

## 進め方の原則

- **機械作業は `ftester remote setup` に委ねる**。この手順書がやるのは
  「聞くこと」「人手が要る項目を人へ渡すこと」「結果の読み方」だけ。
- 各ステップは **exit code で判定**する(パイプで grep に繋がない)。
  `remote setup` の終了コードは install.sh と同じ語彙: **0=完了 / 2=人手の項目が残る / 1=失敗**。
- **人間チェックポイント(🧑)では停止する**。パスワード入力・GUI 設定・物理操作は代行できない。

## 手順

### 0. 必要な値を1回で聞く(AskUserQuestion)

**チャットに質問文を書かない。ダイアログで聞く。** 聞くのは3つだけ:

| 聞くこと | 例 | 補足 |
|---|---|---|
| ランナー機の SSH 宛先 | `user@192.168.20.95` | ホスト名でも可 |
| ランナー機の呼び名(マシンプロファイル名) | `M1Ultra` | **ハードウェア名を勧める**(ホスト名は変わる・社内名が混ざる) |
| 使うプロジェクト | `MyApp` | 手元に1つだけなら聞かずにそれを使う |

**聞かない**(既定でよい): ベースディレクトリ(`~/ftester-runner`)・成果物の回収(既定 collect)。

### 1. 鍵で入れるか確認する

```
ssh -o BatchMode=yes -o ConnectTimeout=10 <宛先> 'echo ok'
```

- `ok` が出れば次へ
- **失敗したら 🧑 に依頼して停止**する(パスワード入力が要るので代行できない):
  `ssh-copy-id <宛先>`(鍵が既定名でなければ `ssh-copy-id -i ~/.ssh/<鍵>.pub <宛先>`)。
  初回のホスト鍵確認(`yes`)もこのとき通してもらう。
  **`StrictHostKeyChecking` を無効化する回避策は提案しない**(未知のホストへプロジェクトを
  送り込む経路を塞いでいる唯一の仕掛け)
- 既定名でない鍵を使う場合、ディスパッチ側も同じ鍵で入る必要がある →
  `~/.ssh/config` に `Host <宛先>` / `IdentityFile` / `IdentitiesOnly yes` を足すよう 🧑 に依頼する

### 2. セットアップを実行する

```
ftester remote setup <宛先> --project <プロジェクト>
```

**初回は数分〜十数分かかる**(clone・xcodegen 導入・`swift build` のコールドビルド)。
逐次1行ずつ出るので、無音でなければ進んでいる。

終了コードで分岐する:

- **0** → ステップ4へ
- **2**(`[warn] preflight: needs manual steps`)→ **ステップ3**(人手の項目が残っている)
- **1** → 出力の `[fail]` 行が原因。よくある3つは下の「詰まったとき」。直して**同じコマンドを再実行**
  (冪等。済んだ工程は skip される)

### 3. 🧑 人手の項目を渡して停止する

`preflight` が列挙した項目を**そのまま**ユーザーへ見せ、ランナー機で実施してもらう。
代表的なもの(すべて sudo か GUI が要るので代行しない):

- リモートログイン ON(システム設定 → 一般 → 共有)・画面共有 ON(推奨)
- `sudo pmset -a sleep 0`(システムスリープ無効。ディスプレイスリープと画面ロックは可)
- **コンソールにログインしたままにする**(ログイン画面のままだとディスパッチは
  「loginwindow で待機中」で止まる。**画面ロックは可**)
- Xcode を手元と同じ版にし、`sudo xcodebuild -license accept` / `xcodebuild -runFirstLaunch`
- Homebrew が**その macOS を知っている版**であること(古いと brew が1つも動かない)

済んだらステップ2を再実行する。

### 4. マシンプロファイルを作る(判断が要る唯一の工程)

ランナー機に**実在するデバイス**を書く必要がある。手元の構成をコピーしない。

```
ftester remote exec <宛先> -- api installed-devices
```

の結果から、`TestProjects/<プロジェクト>/profiles/machines/<マシン名>.json` を作る
(iOS は `name`/`simulator`/`os`/`udid`、Android は `name`/`avd`)。
**プロファイルは手元の資産で、実行のたびに転送される**ので、編集は常に手元だけで行う。

**`"host"` に登録名を入れる**(ステップ0で決めた名前 = `remote hosts add` した名前)。
これが**ディスパッチ先の決定点**で、以後 `--host` を付けなくても実行プロファイルを選ぶだけで
その機械へ飛ぶ。ローカルのマシンプロファイルには書かない(省略 = 手元)。
**ssh の実体(`user@host`)は書けない** —— 登録名だけ。

```jsonc
{ "host": "<登録名>", "ios": { "devices": [{ "name": "iPhone 17 Pro", "udid": "…" }] } }
```

続けて実行プロファイル(`profiles/runs/<名前>.json`)を1つ作る:

- `"machine"` に上のマシン名(**実行プロファイルに `host` は書かない**。マシン経由で決まる)
- `"devices"` はまず**1台**にする(検証を速く回すため)
- **`"heal": false`** にする(ランナー機で Apple Intelligence が無効なことが多い。
  有効なら `true` でよい)

### 5. アプリをランナー機へ置く

**アプリのバイナリは転送されない。** アプリプロファイルの `appPath` は、
**相対パスなら自分の WORK_DIR(`<ベースディレクトリ>/users/<issuerId>/work`)からの位置**に解決される(クローンの中は見ない)。
ランナー機のその位置にビルド済みのアプリを置く(`rsync`/`scp` で送るか、ランナー機でビルドする)。

### 6. 実ディスパッチ1本で検証する(ここが成功の定義)

```
ftester remote setup <宛先> --project <プロジェクト> --profile <実行プロファイル> --scenario <シナリオID>
```

**ビルドが通っただけでは成功ではない。** 実ディスパッチ1本が通って初めて完了。
`✅ [ok] verify: dispatch to <宛先> passed` が出れば導入完了。

以後の実行は **`--host` を付けない**(ステップ4 でマシンプロファイルに `host` を書いてあれば、
実行プロファイルを選ぶだけでその機械へ飛ぶ):

```
ftester run --project <プロジェクト> --profile <実行プロファイル>
```

初回はリモートのコールドビルドで数分、**2回目以降は十数秒**(ブリッジを再利用する)。
今回だけ行き先を変えたいときだけ `--host <登録名>` / `--host local` を足す(明示が勝つ)。

### 7. 完了報告(ユーザーの言語で)

- 実行コマンド(上の `run --host` の形)
- 成果物の場所: レポートと録画は手元の `TestProjects/<プロジェクト>/reports` / `results` へ回収される
- 日常運用の口を3つだけ伝える:
  - `ftester remote status --host <宛先>` — 使える状態か(到達性・ログイン・版・空き容量)
  - `ftester remote clean --host <宛先> --keep-days 7` — **定期的に。**
    ランナー機は誰も見ないので results/録画が溜まり、ある日ディスクフルで止まる
  - `ftester remote setup <宛先>` — **ツールを更新したらこれを流し直す**(版を合わせる。
    更新専用の手順は無い = 導入と同じコマンド。**Xcode/macOS の更新だけは例外**で、
    両機を同じ版に揃える人手の作業が要る)
- モニターの見え方も伝える: **リモートのデバイスも手元と同じようにタイルに映る**
  (状態・ライブ映像・起動/停止。ホスト名のバッジが付くのが違い)。**版が揃っていないと
  状態も映像も来ず**「<ホスト> に届いていません」のままになる —— 版合わせはディスパッチ
  だけの話ではない

## 詰まったとき(頻出の3つ)

| 症状 | 原因 | 対処 |
|---|---|---|
| `git revision mismatch` | 手元とランナー機の版が違う | 手元をコミット&push してから `ftester remote setup <宛先>` を流し直す(align が合わせる)。**手元の未コミットの変更は届かない** |
| `toolchain mismatch` | Xcode / macOS の版が違う | **`remote setup` では直らない**(Xcode の導入は GUI と sudo が要る)。🧑 に両機を同じ版へ揃えてもらう。どちらを動かすかは人の判断 —— 片方を更新した時点で**全ディスパッチが止まる**ので、フリートでは1台だけ更新して検証してから残りへ広げる |
| `is sitting at the login window` | ランナー機がログイン画面 | 🧑 に解錠+ログインを依頼(画面共有で可) |
| `Couldn't fetch updates from remote repositories` / `Recv failure: Operation timed out` | 回線が細く SPM の依存取得が落ちた | **再実行する**(取得済みは残るので数回で通る)。ランナー機で `cd ~/ftester-runner/users/<issuerId>/work && swift package resolve` を先に通しても良い |

これ以外は docs/remote-runner-setup.md の「うまくいかないとき」を読む。
切り分けは**ランナー機で手で実行してみる**のが早い(リモート実行は「向こうで普通に
ローカル実行する」だけなので、同じことが手でもできる)。

## 2台目以降を足すとき

同じ手順を繰り返すだけ。**登録簿に名前を付けておく**(その名前をマシンプロファイルの `host` に
書くと、実行プロファイルの選択だけで行き先が決まる。`--host <名前>` でも指せる):

```
ftester remote hosts add <名前> --host <宛先>
```

複数台へ一斉に流すなら**フリート**を作る(`TestProjects/<プロジェクト>/profiles/fleets/<名前>.json`。
`host` は `"local"` か登録名だけで、ssh 宛先は書けない):

```
ftester run --project <プロジェクト> --fleet <名前>
```

同じホストを2回書いた定義・未登録の名前は**実行前に拒否**される(デバイスの取り合いと、
「走ったつもりで別の場所」を防ぐため)。

**壁時計を縮めたいなら `--split`** —— 同じシナリオを全ホストで回す代わりに、実績から
所要を見積もって台数で分ける(実行前に割り当て表が出る。iOS 専用シナリオは iOS を
走らせられるホストにしか行かない)。

CI から回すなら `--junit <パス>` を足す(全エントリが1ファイルにまとまり、`hostname` で
どの機体か分かる。**出力を出せなかったホストは失敗1件として残る** —— 省くと
「そのホストのぶんは全部通った」に見えるため)。

## 覚えておくこと

- リモート実行分の結果は**そのまま `ftester results` の集計に載る**(回収した results を
  読むだけなので、特別な操作は要らない)
- **手元でコミットしたら push する** —— ランナーは origin から fetch するので、
  押していないコミットには合わせられない(`remote setup` がそう言って止まる)
- リポジトリ外の回避策(`StrictHostKeyChecking` の無効化・ベースディレクトリを
  ランナー機のローカルインストールと同じ場所にする等)
